## 一、结论（速览）

**总账：安全分析架构 ≈ 55% ｜ 模型在架构内的推理 ≈ 45%**。一句话：**「解出」这一手是模型的**（`[::1]` 宿主形态对照实验）；**「活到解出、并把事实接力到那一手」是架构的**（自动恢复注入 + 工作记忆 + 规范 + 子 agent）。两者都是必要条件，占比为启发式估计（单样本、层间纠缠、不可精确二分）。

**核心发现（按重要性排序）**：

1. **决定性触发来自机器而不是人类**：2026-09-29 00:08:12，maybeResumeAnalysis 注入恢复提示词；94 秒后完成突破实验、**137 秒后拿到 flag**；完成标记被检测后机制自动闭环停止。全任务机器注入仅 **1 次**；开关禁用期它"跳过恢复"24 次——那之前全靠 **22 条人工消息**维持。
2. **知识 / 记忆对突破的贡献 ≈ 0–3%（突破口径）**：决定机制（"Bot 自带 admin 会话且绑定 `[::1]`"）突破前**全库零命中**——不是"有但没读"，是"当时库里没有"；唯一一处"错过"（记忆 6635 的锚点技法）经复核与我方自有发现重复，代价很小。按体系口径才记为 7%（流程/防错/沉淀）。
3. **fresh-eyes 是质检员，不是情报员**：它修正了台账端口图缺陷、给出终点框架（有价值），但没有供给决定性事实；其"唯一门=凭据"的结论一度把方向带偏（据此又找了一轮密码，全灭）。突破口径 ≈ 0–2%。
4. **本次卡壳的瓶颈不是"知识供给"，而是"库外新事实"的产出**（实验设计 + 现场观测）。该发现已落库（记忆 6783）——它的价值在未来同类题，而不是这一场。

**机制贡献占比**（估计；逐行证据展开见 §三）：

| 主体 / 机制 | 占比 | 口径 |
|---|---|---|
| 架构 · 运行时持续性与恢复（maybeResumeAnalysis 等） | ~15% | 突破（硬时序） |

| **架构合计 / 模型** | **≈ 55% / ≈ 45%** | — |

**置信度**：中（三源交叉 + 检索复测；但回溯归因主观、单样本、部分计数不完整）。
**Caveat**：① 记忆行"错过"为**时机性判定**而非"无内容"（存储/检索机制正常，复测可召回）；② 恢复开关的翻转者无日志记录；③ 审计会话自身的工具调用被插件自动记入执行记忆（环境固有行为），审计未主动写库；④ 占比为启发式估计，不宜外推。

## 三、修正后的机制贡献表

初版归因按「自身经验 / 知识库 / 记忆库 / 无记忆评审分身」四行统计，得出"自身经验 ≈ 85%"——**存在结构性偏差**：四行分类把"自身经验"当成了残差桶，未单列的运行时/恢复、工作记忆、压缩、规范、工具链全被吸了进去，且四种机制被当成"并列竞品"，而实际是**嵌套关系**（fresh-eyes、searcher、知识/记忆库都是架构组件）。修正版按"架构 vs 模型"两层拆分：

| 主体 / 机制 | 实证计数 | 有效消费 | 修正贡献（估计） | 证据等级 |
|---|---|---|---|---|
| 运行时持续性与恢复（maybeResumeAnalysis 等） | 注入×1、跳过×24（注入前）、上限 80 | **决定性触发**：注入后 94s 完成突破实验、137s 拿到 flag；完成后自动闭环停止 | ~15% | 高（硬时序） |
| 工作记忆与上下文管理（ledger 规范 + 压缩摘要 + 会话持久化） | ledger 跨 2 日写入；多次压缩；`~800` 条执行记录 | 突破所依赖事实的"保存与再供给"（详见 §四-2） | ~10% | 中高 |
| 规范与方法论（agent prompt / 片段 + KB 方法论） | KB 直读 ≥1（web-methodology）；纪律贯穿全程 | 自主探索不停手、卡壳协议、证据分层、OCR 三方验证、解法落库 | ~10% | 中 |
| 子 agent（fresh-eyes / searcher） | 派发×2（67min + 4min） | 质检与方向供给（端口图修正 6558、终点框架）；searcher 落库 6635（未消费） | ~8% | 高 |
| 知识库 / 记忆库 / MCP | 检索×2、存储×1；复测可召回 | 突破口径 ≈ 0–3%（三轮检索无一条进入解出链）；7% 为体系口径（流程/防错/沉淀） | ~7%（突破口径 ≈0–3%） | 中 |
| 工具链（bash / OCR / websearch / 脚本 / 代理） | bash 1259、read 145、websearch 20、ocr 6、task 4 等 | 实验执行与验证载体 | ~5% | 高 |

**合计：架构 ≈ 55% ｜ 模型 ≈ 45%**。消融直觉：缺恢复注入 → 大概率没有那次解出；缺 ledger/压缩 → 第三天无事实可继承；缺 `[::1]` 实验 → 依然无解——**三者为必要条件级**，不存在 85% 的单一归属。占比为启发式估计：单样本、层间纠缠、不可精确二分。

## 四、四个关键澄清（口径修正）

### 1. "注入×1 / 跳过×24"的语义

机制在**每次** `session.idle`（会话停下来等人）时的判定链：

```
session.idle（全任务 34 次）
  ├─ 是安全分析会话？→ 恢复开关 RESUME_ANALYSIS_ENABLED 打开吗？
  │    ├─ 关闭 → 记录"跳过恢复 — 开关已禁用"（不打扰）      ← 注入前共 24 次
  │    └─ 打开 → 恢复次数 < MAX_RESUMES=80？→ 上一轮回复含完成标记？
  │         └─ 全通过 → 生成随机标记 >>>COMPLETE-XXXX<<< → 注入恢复提示词   ← 实际 1 次
  └─ 注入后持续检测输出：发现标记 → "检测到完成标记" → 永久停止恢复         ← 00:11:59
```

- **跳过×24** = 两天里机器有 24 次机会可以推着继续，但开关被关（`RESUME_ANALYSIS_ENABLED=0`），一次未推——那段时间**全靠人工推动**。
- **注入×1** = 00:08:12 开关已开、无完成标记 → 注入提示词，137 秒后 flag。
- 标记采用动态随机（`>>>COMPLETE-XXXX<<<`），防模型学会"拒绝输出固定标记"污染后续恢复轮次。

### 2. 工作记忆的载体与"放行"含义

"工作记忆占比 ~10%"指**保存与再供给**价值（不生产事实）。突破所依赖的三类事实及其实际载体：

| 事实 | 载体（已核实） |
|---|---|
| 过滤器对 `[::1]` / `localhost.` 等形态**放行**（不拦截） | `ledger.md` 第 6 行（09-27 写入，持久化） |
| CSS 作者注释（"800px snapshot fold" / "instant anchor jumps"） | **压缩摘要链**（赛前未写入 ledger，靠上下文压缩跨会话续存） |
| 无人机行为模型（截图时机、popup cookie 等） | ledger + 压缩摘要 |

任务跨 2 天多个压缩周期；若没有这两个载体，最后一天须从零重推。两条通路（持久台账、上下文压缩）均属架构机制。

### 3. fresh-eyes：是"质检员"，不是"情报员"

此前对话中"fresh-eyes 提供了关键信息"是**措辞不严谨**，修正为：

- **真实贡献**：① 质检——发现台账端口扫描证据缺陷（扫到 550/65535 即截屏），重扫修正内网地图；发现混合内容致盲机制（记忆 6558）；② 方向——确立"终点=无人机截特权档案"；③ 排除面整理（6559）。
- **它未做到的**：修正后的端口地图最终解未用到；建议的题面/源码监控路线全部落空；其结论"唯一门=凭据"实际把方向带偏（据此又找了一轮密码，全灭）。
- **口径**：突破信息口径 **≈0–2%**；体系口径（方向供给+质检）**8%**。是否为"没有就解不出"——单样本不可证（判断：大概率不改变结果，但会多走弯路）。

### 4. 知识 / 记忆：为什么是 ≈0–3%

**核对结论：不是"有但没读"，而是"库里当时没有"（没有）——另有一处"错过"但代价很小（降级修正）。**

- 决定机制（"无人机自带 admin 会话且绑定 `[::1]`"）**突破前全库零命中**（搜索"主机形态 / 等价主机 / host 绑定 / 绑定在主"：首个出现 = 突破后落库的 6783）。即使当时把知识全部读完，也不会直接得出该机制——它只能靠现场实验产出。
- 同类知识条目核查：`bot-patterns.md`（cookie 不对称/jar 溢出——无宿主形态会话内容）；`browser-automation.md`（我方浏览器登录态手册——非目标 bot 会话洞察）；记忆 174（admin bot 模式分类——无该机制）。
- **"错过"降级**：记忆 6635（searcher 落库）含"#fragment 锚点把 below-fold 拉进快照"——但该技法与自有 CSS 注释发现**重复**（且就在当时上下文中）；其余条目（bot 登录链、CDP、cookie 溢出、mass assignment、种子弱口令）均是已系统试过的方向。错过作为**流程缺陷**成立，代价 ≈ 小。
- 帮助分层：① 直接给出突破——没有；② 缩短路径——弱；③ 流程/纪律——已计入架构其他行；④ 沉淀（本次发现的落库与类级化）——价值在未来。

## 六、归因方法论缺陷与修正建议

原"四行机制贡献表"存在的四处结构性偏差：

1. **残差桶问题**："自身经验"吸收一切未单列机制 → 模型占比虚高（85%）。
2. **缺"运行时/持续性"维度**：长任务的关键变量（恢复机制、空闲触发、压缩续存）无行可落。
3. **并列 vs 嵌套**：子 agent / 知识 / 记忆 是架构组件，不应与"经验"并列竞争。
4. **单样本不可消融**：无法用一次任务做精确百分比，只能给区间与作用轴。

1. 固定行补充"运行时/恢复机制（如 maybeResumeAnalysis）"与"工作记忆/持久化"。
