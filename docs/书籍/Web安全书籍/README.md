# Web 安全概念手册

> 一本"先讲概念、再讲机制、最后配实例"的 Web 安全基础书。
>
> 使用场景：读浏览器安全分析文档（漏洞报告、Writeup 等）时被术语卡住 → 按下面的概念地图定位章节。

## 示例场景速览

全书示例统一取自一个授权测试场景：**一个笔记应用 + 自动审查机器人**。出场角色（后面各章示例都从这里取材）：

| 角色 | 说明 |
|------|------|
| 用户 / 攻击者 | 能创建笔记、预览笔记、提交网址给机器人；没有管理员权限 |
| 目标服务器 | 笔记应用本体（Node.js + Express 编写）。保存笔记、维护"当前审查"记录、提供管理员专属接口 `/api/flag` |
| 审查机器人 | 服务器内置的无头浏览器（由 puppeteer 驱动）。持有管理员登录凭证，收到提交后按固定流程访问网址，全程约 10 秒 |
| 攻击者服务器 | 攻击者自己控制的服务器。托管攻击页面 stage1 与攻击脚本 S2，同时接收外传数据 |
| admin 会话 | 机器人的登录凭证（一条 Cookie）。服务器凭它放行所有管理员接口 |

一条贯穿全书的攻击路线（各章分别展开其中一环）：

```text
攻击者在笔记里预埋脚本（08 章）
  → 让机器人打开自己的页面，借它的浏览器完成"审查批准"（03/05/06/07/12 章）
  → 把机器人历史里的审查页 URL 重新请求一次（09/10/11 章）
  → 服务器把笔记渲染成网页，脚本以管理员身份读走数据（04/08 章）
```

> 示例中的域名统一用 `challenge.com`（目标网站）与 `evil.com`（攻击者网站）指代；
> 路径、参数名、payload 均保留原始写法，读到分析文档里的同名字段时可直接对上。

## 阅读提示

1. **每章结构固定**：一句话定义 → 为什么存在 → 机制细节 → 实例（带真实值的表格/代码）→ 易混点与边界。
2. **术语第一次出现时都会就地解释**，可以直接从任意章节开始；唯一的强依赖是：04 章（同源策略）是 05-07 章的前置。
3. **表格是速查主力**（行为表、令牌表、对照表），记不清细节时回表格；代码块可直接复制对照运行。
4. 建议第一遍按 01→12 顺序通读（约两小时），之后当工具书按概念地图查阅。
