# 知识与记忆体系：读写机制详解

## 概述

OpenSecurity 构建了三层记忆体系，对齐 PentAGI 的设计，但适配 OpenCode 的 MCP + Plugin 架构：

| 层 | 存储后端 | MCP Server | 隔离方式 | 定位 |
|----|---------|-----------|---------|------|
| **知识沉淀** | SQLite + sqlite-vec（本地） | knowledge MCP | 全局共享 | 跨任务复用的精炼知识 |
| **执行记忆** | SQLite + sqlite-vec（本地） | knowledge MCP（doc_type=memory） | 按 flow_id 隔离 | 当前任务的工具执行记录 |
| **事件图谱** | Neo4j（Docker 容器） | events MCP | 按 group_id 隔离 | 当前任务的实体关系图谱 |

> flow_id 和 group_id 是同一个值的不同命名（`session.flowId` → `$OPENSECURITY_FLOW_ID` → MCP 工具的 `group_id` 参数）。主任务和它的所有子任务共享同一个值。

## 一、知识沉淀（knowledge 向量库 — answer/guide/code）

### 1.1 四种 doc_type

| doc_type | 定位 | 举例 | 隔离 |
|----------|------|------|------|
| **answer** | 分析结论（"是什么"） | "CVE-2024-XXXX 是栈溢出，利用方法是 ROP 链" | 全局 |
| **guide** | 操作步骤（"怎么做"） | "如何配置 Frida server 绕过 SSL Pinning" | 全局 |
| **code** | 可复用代码 | "通用 ROP chain 生成脚本" | 全局 |
| **memory** | 工具执行记录（自动） | nmap 扫描的实际输出 | 按 flow_id |

answer/guide/code 是**领域 agent 主动存储**的精炼知识——全局共享，跨任务复用。
memory 是**插件自动存储**的工具执行记录——按任务隔离，只在当前任务内可搜。

### 1.2 谁写、何时写

#### answer（分析结论）

```
触发：领域 agent（binary/mobile/web/crypto/ai-security）得出明确分析结论后
写入者：领域 agent 直接调 mcp__knowledge__store_answer
写入内容：question（"未来谁会查这条知识"的角度）+ answer（漏洞描述+利用方法+验证结果）
匿名化：MCP 工具内置 anonymize()，自动清洗 IP/凭证/域名
```

#### guide（操作步骤）

```
触发：领域 agent 总结出可复用的操作步骤/配置方法
写入者：领域 agent 直接调 mcp__knowledge__store_guide
写入内容：guide（操作步骤文本）+ question（关联问句）+ type（install/configure/use/pentest/development/other）
匿名化：同上
```

#### code（可复用代码）

```
触发：领域 agent 写出可复用的 PoC/exploit/脚本
写入者：领域 agent 直接调 mcp__knowledge__store_code
写入内容：code（源码）+ question（关联问句）+ lang（编程语言）+ explanation（说明）+ description（摘要）
匿名化：同上
```

#### memory（工具执行记录）

```
触发：插件 tool.execute.after hook 自动触发（领域 agent 无感）
写入者：插件 fireAndForgetMemory → memory_writer_daemon.py → SQLite
白名单：只存有信息价值的工具结果
  ✅ bash（命令输出）、read（文件内容）、websearch/webfetch（外部资料）、task（子 agent 返回）
  ❌ write/edit（写操作）、glob/grep（搜索操作）、mcp__knowledge__*（向量库操作）、mcp__events__*（事件库操作）
隔离：存入 flow_id（当前任务的 Flow ID）
匿名化：memory_writer_daemon 内置
```

### 1.3 谁读、何时读

#### answer/guide/code 的读取

```
读取者：searcher agent（被领域 agent 委派时）
触发时机：
  - 领域 agent 需要确定分析方向时 → 委派 searcher（Task 工具，subagent_type=searcher）
  - 委派 prompt 描述目标的关键特征（目标类型 + 已知技术特征）
searcher 内部决策：
  - [1] search_answer（必起手）→ 查是否已有同类分析结论
  - search_guide → 需要"怎么做"的操作指引时
  - search_code → 需要参考类似场景的代码时
返回：searcher 综合结果返回摘要给领域 agent
```

领域 agent **不直接调** search_answer/search_guide/search_code——统一委派 searcher 查询。这是设计决策：逻辑收口，由检索专家（searcher）构造最优查询。

#### memory 的读取

```
读取者：memorist agent（被领域 agent 委派时）
触发时机：领域 agent 需要回顾当前任务的历史操作
memorist 调 mcp__knowledge__search_in_memory：
  - 参数 flow_id（从 system prompt 的 $OPENSECURITY_FLOW_ID 获取）
  - 只返回当前任务的工具执行记录
返回：匹配的执行记录摘要
```

### 1.4 读写路径全景图

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        知识沉淀（answer/guide/code）                      │
│                        全局共享 — 跨任务复用                              │
│                                                                         │
│  写：领域 agent ──→ mcp__knowledge__store_answer / store_guide /         │
│  （得出结论后）      store_code（直接调，内置匿名化）                      │
│                                                                         │
│  读：领域 agent ──→ Task(searcher) ──→ mcp__knowledge__search_answer /   │
│  （需要确定方向时）                       search_guide / search_code      │
│                                          ──→ 返回摘要                    │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│                        执行记忆（memory）                                 │
│                        按 flow_id 隔离 — 只在当前任务内可搜               │
│                                                                         │
│  写：插件 tool.execute.after hook                                       │
│  （每次工具执行后）  ├── 白名单检查（bash/read/websearch/webfetch/task） │
│                     ├── fireAndForgetMemory(toolName, args, output,     │
│                     │     flowId)                                       │
│                     └── memory_writer_daemon ──→ SQLite                │
│                                                                         │
│  读：领域 agent ──→ Task(memorist) ──→ mcp__knowledge__search_in_memory │
│  （需要回顾历史时）                      （flow_id=$OPENSECURITY_FLOW_ID) │
│                                         ──→ 返回当前任务的执行记录       │
└─────────────────────────────────────────────────────────────────────────┘
```

## 二、事件图谱（events 事件库 — Neo4j）

### 2.1 定位

事件库存储当前任务的**结构化知识图谱**——实体（Entity）、关系（Edge）、事件（Episode）。由 Graphiti 自动从文本中提取实体和关系，构建可查询的图谱。

与 knowledge 向量库的区别：
- knowledge = 语义搜索（"搜类似的文本"）
- events = 图谱查询（"找中心节点的邻居"/"时间窗口内的事件"/"哪些工具成功过"）

### 2.2 谁写、何时写

```
全部由插件自动写入（领域 agent 无感）：

1. tool.execute.after hook
   触发：每次工具执行后（排除 task 工具）
   写入：fireAndForgetEvent → write_event_daemon.py → Graphiti → Neo4j
   内容：工具名 + 参数 + 结果 + agent 名
   隔离：group_id = session.flowId（$OPENSECURITY_FLOW_ID）
   实体提取：Graphiti 内部用 DeepSeek API 从文本提取实体/关系

2. text.complete hook
   触发：每次 LLM 响应后
   写入：fireAndForgetEvent → write_event_daemon.py → Graphiti → Neo4j
   内容：agent 名 + LLM 响应文本
   隔离：同上
```

### 2.3 谁读、何时读

```
读取者：memorist agent（被领域 agent 委派时）
触发时机：领域 agent 需要查当前任务的历史

memorist 的查询路径：
  [1] 事件库搜索（情景记忆优先）→ 7 种搜索类型任选合适的：
      ├── mcp__events__recent_context_search     → 最近发生了什么（默认起始点）
      ├── mcp__events__episode_context_search    → 某 agent 做了什么/发现了什么
      ├── mcp__events__temporal_window_search    → 特定时间段内发生了什么
      ├── mcp__events__successful_tools_search   → 哪些工具/技术成功过
      ├── mcp__events__entity_relationships_search → 探索实体间关系（需 UUID）
      ├── mcp__events__entity_by_label_search    → 按类型列出实体清单
      └── mcp__events__diverse_results_search    → 获取多元视角

  [2] mcp__knowledge__search_in_memory（执行记忆补充）
      → 查当前任务的工具执行记录（向量语义搜索）

  [3] Read / Glob / Grep / Bash
      → 读 $ROOT_TASK_DIR 下的文件（报告、脚本、日志）
```

### 2.4 读写路径全景图

```
┌─────────────────────────────────────────────────────────────────────────┐
│                        事件图谱（events — Neo4j）                        │
│                        按 group_id 隔离 — 只在当前任务内可搜              │
│                                                                         │
│  写：插件自动（领域 agent 无感）                                          │
│  ├── tool.execute.after hook                                            │
│  │   └── fireAndForgetEvent → write_event_daemon → Graphiti → Neo4j    │
│  │       （工具执行记录 → DeepSeek 提取实体/关系 → 存入图谱）             │
│  │                                                                       │
│  └── text.complete hook                                                 │
│      └── fireAndForgetEvent → write_event_daemon → Graphiti → Neo4j    │
│          （LLM 响应文本 → DeepSeek 提取实体/关系 → 存入图谱）             │
│                                                                         │
│  读：领域 agent ──→ Task(memorist) ──→ mcp__events__*（7 种搜索）       │
│  （需要回顾历史时）                      （group_id=$OPENSECURITY_FLOW_ID)│
│                                         ──→ 返回实体/关系/事件           │
└─────────────────────────────────────────────────────────────────────────┘
```

## 三、三层记忆的协作关系

### 3.1 一次完整安全分析中的记忆流转

```
Step 1: 接到新分析任务
│
├── 领域 agent（如 binary-analysis）开始分析
│   ├── 阶段 A：信息收集（检测文件类型/架构等）
│   │
│   └── 需要确定分析方向时
│       └── Task(searcher)：「查是否已有同类目标的分析记录」
│           ├── searcher 调 search_answer → 查 knowledge(answer)
│           │   └── 查到 → 复用已有结论，加速分析
│           │   └── 查不到 → 正常分析
│           ├── searcher 调 search_guide → 查 knowledge(guide)
│           └── searcher 调 websearch/webfetch → 外部搜索
│               └── 返回摘要给领域 agent
│
Step 2: 执行分析
│
├── 领域 agent 执行工具（Bash/Read/IDA 等）
│   ├── 每次工具执行后，插件自动写入：
│   │   ├── events 事件库（工具执行记录 → Graphiti 提取实体/关系）
│   │   └── knowledge memory（工具结果，按 flow_id 隔离）
│   │
│   ├── 每次 LLM 响应后，插件自动写入：
│   │   └── events 事件库（LLM 响应文本 → Graphiti 提取实体/关系）
│   │
│   └── 遇到不熟悉的技术时
│       └── Task(searcher)：「查 CVE-XXXX 利用方法」
│           └── searcher 调 websearch/webfetch → 返回外部资料
│
Step 3: 得出分析结论
│
├── 领域 agent 确认漏洞/绕过/算法还原
│   ├── mcp__knowledge__store_answer → 存分析结论到 knowledge(answer)
│   ├── mcp__knowledge__store_guide → 存操作步骤到 knowledge(guide)（如有）
│   └── mcp__knowledge__store_code → 存 PoC/脚本到 knowledge(code)（如有）
│       （存储时自动匿名化 IP/凭证/域名）
│
Step 4: 需要回顾历史时
│
├── 领域 agent 委派 memorist
│   └── Task(memorist)：「查当前任务之前做了什么」
│       ├── memorist 调 mcp__events__recent_context_search
│       │   → 查事件图谱（当前任务的实体关系/时间线）
│       ├── memorist 调 mcp__knowledge__search_in_memory
│       │   → 查执行记忆（当前任务的工具执行记录）
│       └── memorist 读 $ROOT_TASK_DIR 文件
│           → 返回历史摘要给领域 agent
│
Step 5: 下次同类任务
│
└── 新任务开始 → Task(searcher) → search_answer
    └── 找到 Step 3 存的结论 → 复用 → 加速
```

### 3.2 三层记忆对比

| 维度 | 知识沉淀（answer/guide/code） | 执行记忆（memory） | 事件图谱（events） |
|------|---------------------------|-------------------|------------------|
| **存储后端** | SQLite + sqlite-vec | SQLite + sqlite-vec（同库不同 doc_type） | Neo4j（Docker） |
| **MCP Server** | knowledge MCP | knowledge MCP | events MCP |
| **隔离** | 全局共享 | 按 flow_id | 按 group_id（= flow_id） |
| **谁写** | 领域 agent 主动调 store_* | 插件自动（fireAndForgetMemory） | 插件自动（fireAndForgetEvent） |
| **何时写** | 得出分析结论后 | 每次工具执行后（白名单内） | 每次工具执行 + 每次 LLM 响应 |
| **谁读** | searcher（被委派时） | memorist（被委派时） | memorist（被委派时） |
| **何时读** | 需要确定分析方向时 | 需要回顾当前任务操作时 | 需要查当前任务实体关系时 |
| **查询方式** | 向量语义搜索（BGE-M3 cosine） | 向量语义搜索（同上） | 图谱查询（BFS/时间窗口/实体标签） |
| **匿名化** | MCP 工具内置 anonymize | daemon 内置 anonymize | Graphiti 内置 |
| **清理时机** | 手动（clean_databases.py） | session 删除时不自动清理 | session 删除时自动清理（deleteGraphitiEvents） |

### 3.3 Agent 职责分工

| Agent | 知识沉淀（answer/guide/code） | 执行记忆（memory） | 事件图谱（events） |
|-------|---------------------------|-------------------|------------------|
| **领域 agent**（binary/mobile/web/crypto/ai-security） | 写（store_*） | 不直接操作（插件自动） | 不直接操作（插件自动） |
| **searcher** | 读（search_*） | 不读 | 不读 |
| **memorist** | 不读 | 读（search_in_memory） | 读（events 7 种搜索） |
| **coordinator** | 不直接操作 | 不直接操作 | 不直接操作 |

领域 agent 通过 `{{buwai-rule:knowledge-management}}` 共享片段获得知识管理指引：
- 查知识 → 委派 searcher
- 存结论 → 直接调 store_answer/store_guide/store_code

## 四、技术实现细节

### 4.1 knowledge MCP 架构

```
knowledge/server.py（FastMCP）
  ├── lifespan lazy 加载（BGE-M3 后台加载，不阻塞握手）
  ├── 7 个 MCP 工具：
  │   ├── search_answer / store_answer（doc_type=answer）
  │   ├── search_guide / store_guide（doc_type=guide）
  │   ├── search_code / store_code（doc_type=code）
  │   └── search_in_memory（doc_type=memory，按 flow_id 隔离）
  ├── 匿名化：store_* 工具内置 anonymize()
  ├── 向量搜索：BGE-M3 embed content + sqlite-vec cosine similarity
  └── score 阈值：0.2（低于此值不返回）
```

### 4.2 events MCP 架构

```
events/server.py（FastMCP）
  ├── lifespan lazy 加载（Docker + Neo4j + BGE-M3 后台加载）
  ├── 8 个 MCP 工具：
  │   ├── 7 种搜索（temporal_window/entity_relationships/diverse_results/
  │   │            episode_context/successful_tools/recent_context/entity_by_label）
  │   └── delete_session_events（按 group_id 删除）
  ├── 后端：Graphiti（Neo4j + DeepSeek API 实体提取 + BGE-M3 embedding + bge-reranker）
  └── 隔离：group_id 参数（= $OPENSECURITY_FLOW_ID）
```

### 4.3 插件自动写入机制

```
security-analysis.ts 的 hooks：

tool.execute.after（工具执行后）
  ├── fireAndForgetEvent（→ write_event_daemon → Graphiti → Neo4j）
  │   写入：工具名 + 参数 + 结果 + agent 名
  │   隔离：group_id = session.flowId
  │
  └── fireAndForgetMemory（→ memory_writer_daemon → SQLite）
      白名单：bash/read/websearch/webfetch/task
      写入：工具名 + 参数 + 结果
      隔离：flow_id = session.flowId

text.complete（LLM 响应后）
  └── fireAndForgetEvent（→ write_event_daemon → Graphiti → Neo4j）
      写入：agent 名 + LLM 响应文本
      隔离：group_id = session.flowId
```

### 4.4 pyproject.toml 单一事实源

每个 MCP server 的 pyproject.toml 声明依赖和运行时元数据：

```toml
# events/pyproject.toml
[tool.opensecurity]
import_names = ["mcp", "graphiti_core"]
requires_docker = "neo4j-events"

# knowledge/pyproject.toml
[tool.opensecurity]
import_names = ["mcp", "sentence_transformers", "sqlite_vec"]
# 无 requires_docker（不需要 Docker）
```

detect_env.py 从 pyproject.toml 读取元数据（不硬编码），check-preinstall 路径只检测不启动。

## 五、数据清理

使用 `.opencode/tools/clean_databases.py` 清理历史数据/测试数据：

```bash
# 查看数据量（不删除）
python .opencode/tools/clean_databases.py --dry-run

# 清理两个数据库（需确认）
python .opencode/tools/clean_databases.py

# 只清理 events（Neo4j）
python .opencode/tools/clean_databases.py --events

# 只清理 knowledge（SQLite）
python .opencode/tools/clean_databases.py --knowledge
```

events 清理：删除所有节点、关系、索引、约束。
knowledge 清理：删除所有记录（answers + answer_vectors）。

session 删除时 events 自动清理（deleteGraphitiEvents），knowledge 不自动清理（memory 按 flow_id 隔离但不会随 session 删除而删除）。
