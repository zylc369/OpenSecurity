# 知识与记忆体系：读写机制详解

## 概述

OpenSecurity 构建了三层记忆体系，对齐 PentAGI 的设计，但适配 OpenCode 的 MCP + Plugin 架构：

| 层 | 存储后端 | MCP Server | 隔离方式 | 定位 |
|----|---------|-----------|---------|------|
| **知识沉淀** | SQLite + sqlite-vec（本地） | knowledge MCP（`mcp-servers/knowledge/server.py`） | 全局共享 | 跨任务复用的精炼知识 |
| **执行记忆** | SQLite + sqlite-vec（同库，doc_type=memory） | knowledge MCP（同上，`search_in_memory` 工具） | 按 flow_id 隔离 | 当前任务的工具执行记录 |
| **事件图谱** | Neo4j（Docker 容器 `neo4j-events`） | events MCP（`mcp-servers/events/server.py`） | 按 group_id 隔离 | 当前任务的实体关系图谱 |

> **flow_id = group_id = $OPENSECURITY_FLOW_ID**，是同一个值的不同命名：
> - `session.flowId`（plugin 内部变量，`security-analysis.ts` 的 `SessionData` 类）
> - `$OPENSECURITY_FLOW_ID`（注入到 bash 环境变量，`security-analysis.ts:1140` 的 `shell.env` hook）
> - `group_id`（events MCP 工具参数，`events/server.py` 各搜索工具的 `group_id` 参数）
> - `flow_id`（knowledge MCP `search_in_memory` 工具的 `flow_id` 参数，`knowledge/server.py:225`）
>
> 主任务和它的所有子任务共享同一个值。子 session 通过 `session-manager.ts` 的 `flowId` 继承机制获得。

## 一、知识沉淀（knowledge 向量库 — answer/guide/code/memory）

### 1.1 两种 doc_type

| doc_type | 定位 | 举例 | 隔离 | 谁写 |
|----------|------|------|------|------|
| **knowledge** | 精炼知识（分析结论、操作步骤、可复用代码） | "CVE-2024-XXXX 是栈溢出，利用方法是 ROP 链"；"如何配置 Frida server 绕过 SSL Pinning"；"通用 ROP chain 生成脚本" | 全局 | 领域 agent 调 `store_knowledge` |
| **memory** | 工具执行记录（自动） | nmap 扫描的实际输出 | 按 flow_id | 插件自动（`fireAndForgetMemory`） |

knowledge 是**领域 agent 主动存储**的精炼知识——全局共享，跨任务复用。不区分类型（原 answer/guide/code 已合并），靠 BGE-M3 语义搜索区分。
memory 是**插件自动存储**的工具执行记录——按任务隔离，只在当前任务内可搜。

### 1.2 数据库结构

**文件**：`mcp-servers/knowledge/db.py` → `MemoryDB` 类（行 68）

**表结构**（`db.py:41-58`）：
```sql
-- answers 表（普通 SQLite 表）
CREATE TABLE answers (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    question TEXT NOT NULL,          -- 关联问句
    answer TEXT NOT NULL,            -- content 文本（embed 目标）
    type TEXT NOT NULL,              -- 弃用（兼容旧数据），新数据写 doc_type 值
    doc_type TEXT NOT NULL DEFAULT 'knowledge',  -- knowledge/memory
    guide_type TEXT NOT NULL DEFAULT '',      -- 弃用（兼容旧数据）
    code_lang TEXT NOT NULL DEFAULT '',        -- lang 参数写入此处（python/bash/golang 等）
    flow_id TEXT DEFAULT NULL,                 -- 仅 memory 用（按任务隔离）；knowledge 为 NULL
    created_at REAL NOT NULL
);

-- answer_vectors 表（vec0 虚拟表，sqlite-vec）
CREATE VIRTUAL TABLE answer_vectors USING vec0(
    embedding float[1024] distance_metric=cosine
);
```

**迁移机制**（`db.py:61-64, 96-111`）：`MIGRATE_COLUMNS` 列表定义需要检查的列。`flow_id` 列有特殊迁移逻辑——如果旧数据库是 `NOT NULL DEFAULT ''`，会 DROP + ADD 重建为 `TEXT DEFAULT NULL`。

**向量搜索**（`db.py:149-210`）：
- embed 目标：`answer`（content 文本），不是 `question`
- 模型：BGE-M3（1024 维）
- 距离度量：cosine（sqlite-vec 返回 `1 - cosine_similarity`）
- score 阈值：`SCORE_THRESHOLD = 0.2`（`db.py:39`，低于此值不返回）
- flow_id 过滤（`db.py:197-200`）：仅 `doc_type == "memory" and flow_id is not None` 时生效

### 1.3 MCP 工具定义

**文件**：`mcp-servers/knowledge/server.py`

每个工具使用 `Annotated[Type, Field(description="...")]` 定义参数——FastMCP 自动提取到 JSON schema，OpenCode 每轮注入到 LLM 的 tools 参数。**LLM 从 schema 就知道工具做什么、参数填什么、枚举选什么**，不依赖 agent prompt。

| 工具 | 功能 | doc_type | 关键参数 |
|------|------|----------|---------|
| `search_knowledge` | 检索已有知识（必起手） | knowledge | `questions`（中文问句）+ `lang`（可选过滤） |
| `store_knowledge` | 存储新知识 | knowledge | `question` + `content` + `lang`（可选） |
| `search_in_memory` | 检索执行记忆 | memory | `questions` + `flow_id`（按任务隔离） |

所有工具还有 `message` 参数（操作日志，1-2 句中文描述你正在做什么）。

**匿名化**（`server.py` 的 store_knowledge 内调 `anonymize()`）：
- 文件：`mcp-servers/knowledge/anonymizer.py`
- 清洗内容：IP、邮箱、API key、AWS key、credential、bearer token、SSH key、DB connection string、domain

**启动模式**（`server.py:44-86` lifespan lazy 加载）：
- 模块顶层不加载 BGE-M3，stdio 握手快（<2s）
- lifespan startup 内 `run_in_executor` 后台加载模型（fire-and-forget）
- 工具函数开头 `await _ensure_ready()`（行 81）等待模型加载完成

### 1.4 谁写、何时写

#### answer/guide/code（领域 agent 主动写）

```
触发：领域 agent 得出明确分析结论后
      引导来源：agents-rules/knowledge-management.md（共享片段，5 个领域 agent 通过 {{buwai-rule:knowledge-management}} 引用）

写入者：领域 agent 直接调 MCP 工具（不经 searcher）
  store_knowledge → server.py → anonymize(question) + anonymize(content) → db.store(doc_type="knowledge", flow_id=None)

flow_id：None（全局共享，跨任务可搜）
```

#### memory（插件自动写）

```
触发：插件 tool.execute.after hook（security-analysis.ts:1218）
      每次 agent 执行工具后自动触发

调用链：
  security-analysis.ts:1264 → fireAndForgetMemory(toolName, args, output, session.flowId)
    ↓ security-analysis.ts:712 白名单检查（MEMORY_ALLOWED_TOOLS）
    ↓ security-analysis.ts:720 fireAndForgetMemory → JSON {question, answer, type, flow_id}
    ↓ stdin 管道 → memory_writer_daemon.py:36 解析 JSON
    ↓ memory_writer_daemon.py:47 db.store(flow_id=entry.get("flow_id") or None)
    ↓ knowledge/db.py:118 MemoryDB.store → SQLite INSERT

白名单（security-analysis.ts:712-718）：
  ✅ bash、read、websearch、webfetch、task
  ❌ write、edit、glob、grep、mcp__knowledge__*、mcp__events__*

flow_id：当前任务的 session.flowId（按任务隔离，只在本任务内可搜）
```

### 1.5 谁读、何时读

#### knowledge（searcher 读 + 领域 agent 直接调）

```
读取者：
  1. searcher agent（被领域 agent 委派时，Task 工具 subagent_type=searcher）——复杂检索
  2. 领域 agent 直接调 mcp__knowledge__search_knowledge——简单检索（操作指引/可复用代码）
引导来源：
  - agents/searcher.md：搜索流程 + 决策树 + 语言策略
  - agents-rules/knowledge-management.md：领域 agent 何时委派 searcher / 何时直接调 search_knowledge

调用链：
  searcher/领域 agent → mcp__knowledge__search_knowledge
                     → db.search(doc_type="knowledge", lang=...)
                     → 返回 JSON {results: [{id, question, answer, score}], count}
```

#### memory（memorist 读）

```
读取者：memorist agent（被领域 agent 委派时，Task 工具 subagent_type=memorist）
引导来源：agents/memorist.md

memorist 调用链：
  memorist → mcp__knowledge__search_in_memory（server.py:225）

           → 返回当前任务的工具执行记录
```

## 二、事件图谱（events 事件库 — Neo4j）

### 2.1 定位

事件库存储当前任务的**结构化知识图谱**——实体（Entity）、关系（Edge）、事件（Episode）。由 Graphiti 自动从文本中提取实体和关系，构建可查询的图谱。

| 维度 | knowledge 向量库 | events 事件库 |
|------|-----------------|-------------|
| 查询方式 | 向量语义搜索（"搜类似的文本"） | 图谱查询（"找中心节点的邻居"/"时间窗口内的事件"） |
| 数据格式 | 非结构化文本 + 向量 | 结构化节点/边/事件片段 |
| 实体提取 | 无 | Graphiti 内部用 DeepSeek API 自动提取 |

### 2.2 MCP 工具定义

**文件**：`mcp-servers/events/server.py`

| 工具 | 功能 | 关键参数 |
|------|------|---------|
| `time_search` | 按时间搜索（不传=全部；传起始=最近；传起止=区间） | `query` + `group_id` + `time_start`(可选) + `time_end`(可选) |
| `entity_relationships_search` | 从中心节点 BFS | `query` + `group_id` + `center_node_uuid` + `max_depth` |
| `diverse_results_search` | MMR 多元搜索 | `query` + `group_id` + `diversity_level`（low/medium/high） |
| `episode_context_search` | 搜索事件片段 | `query` + `group_id` |
| `entity_search` | 按标签搜索实体（可选按提及次数过滤） | `query` + `group_id` + `node_labels` + `min_mentions`(可选) |
| `delete_session_events` | 删除任务数据 | `group_id` |

所有搜索工具都有 `message` 参数 + 所有参数使用 `Annotated + Field` 中文描述。

**启动模式**（`server.py:36-200` lifespan lazy 加载）：
- lifespan 子线程顺序执行：Docker daemon 启动 → neo4j-events 容器启动 → BGE-M3 加载
- 握手快（fire-and-forget），工具调用时 `await _ensure_ready()`（行 210）等待全部就绪
- `_ensure_ready` 内含 `asyncio.wait_for(_ready.wait(), timeout=60)`（行 215）——最多等 60 秒

**后端**（`mcp-servers/events/graphiti_config.py`）：
- LLM：DeepSeek API（deepseek-v4-pro/flash，实体提取）
- Embedding：BGE-M3 本地模型（`graphiti_config.py:84` BgeM3Embedder）
- CrossEncoder：bge-reranker-v2-m3 本地模型（`reranker.py` BgeRerankerClient）
- 存储：Neo4j（bolt://localhost:7687）

### 2.3 谁写、何时写

```
全部由插件自动写入（领域 agent 无感）：

1. tool.execute.after hook（security-analysis.ts:1218）
   触发：每次工具执行后（排除 task 工具）
   调用链：
     security-analysis.ts:1259 fireAndForgetEvent(toolName, body, source, session.flowId)
       ↓ security-analysis.ts:571 fireAndForgetEvent → JSON {name, body, source, group_id, timestamp}
       ↓ stdin 管道 → write_event_daemon.py:38 消费队列
       ↓ write_event_daemon.py:29 MAX_CONCURRENT=10 Semaphore 限流
       ↓ graphiti.add_episode() → DeepSeek 提取实体/关系 → Neo4j 存储
   隔离：group_id = session.flowId

2. text.complete hook（security-analysis.ts:1282）
   触发：每次 LLM 响应后
   调用链：同上（fireAndForgetEvent）
   内容：agent 名 + LLM 响应文本
```

**write_event_daemon.py**（`mcp-servers/events/write_event_daemon.py`）：
- 常驻 Python 进程，通过 stdin 管道接收事件（line-delimited JSON）
- 并发模型：`asyncio + Semaphore(10) + 无界 Queue`（行 9, 29）
- 支持 `action: "delete"` 消息（行 48-54）→ `EntityNode.delete_by_group_id` + `EpisodicNode.delete_by_group_id`

### 2.4 谁读、何时读

```
读取者：memorist agent（被领域 agent 委派时）
引导来源：agents/memorist.md

memorist 的查询路径（memorist.md:41-46）：
  [1] 事件库搜索（情景记忆优先）→ 7 种搜索类型任选合适的（见 2.2 工具表）
  [2] mcp__knowledge__search_in_memory（执行记忆补充）
  [3] Read / Glob / Grep / Bash → 读 $ROOT_TASK_DIR 下的文件

所有 events 搜索工具传 group_id = $OPENSECURITY_FLOW_ID（限定到当前任务）
```

## 三、三层记忆的协作关系

### 3.1 一次完整安全分析中的记忆流转

```
Step 1: 接到新分析任务
│
├── 领域 agent（如 binary-analysis）开始分析
│   ├── 阶段 A：信息收集（检测文件类型/架构等）
│   │   （工具执行 → 插件自动写入 events + memory）
│   │
│   └── 需要确定分析方向时
│       ├── Task(searcher)：「查是否已有同类目标的分析记录」
│       │   ├── search_knowledge → 查 knowledge(knowledge)
│       │   │   └── 查到 → 复用已有结论，加速分析
│       │   │   └── 查不到 → 正常分析
│       │   └── websearch/webfetch → 外部搜索
│       │       └── 返回摘要给领域 agent
│       │
│       └──（需要操作指引或可复用代码时）直接调 search_knowledge → 查 knowledge(knowledge)
│
Step 2: 执行分析
│
├── 领域 agent 执行工具（Bash/Read/IDA 等）
│   ├── 每次工具执行后，插件自动写入（security-analysis.ts:1218 tool.execute.after）：
│   │   ├── fireAndForgetEvent（security-analysis.ts:571）→ events 事件库
│   │   └── fireAndForgetMemory（security-analysis.ts:720）→ knowledge memory
│   │       └── 白名单检查（security-analysis.ts:712 MEMORY_ALLOWED_TOOLS)
│   │
│   ├── 每次 LLM 响应后，插件自动写入（security-analysis.ts:1282 text.complete）：
│   │   └── fireAndForgetEvent → events 事件库
│   │
│   └── 遇到不熟悉的技术时
│       └── Task(searcher)：「查 CVE-XXXX 利用方法」
│           └── searcher 调 websearch/webfetch → 返回外部资料
│
Step 3: 得出分析结论
│
├── 领域 agent 确认漏洞/绕过/算法还原
│   └── mcp__knowledge__store_knowledge → 存分析结论/操作步骤/PoC 脚本
│       （存储时自动 anonymize() 清洗 IP/凭证/域名；代码为主的内容传 lang 参数）
│
Step 4: 需要回顾历史时
│
├── 领域 agent 委派 memorist
│   └── Task(memorist)：「查当前任务之前做了什么」
│       ├── mcp__events__time_search（不传时间=搜全部）
│       │   → 查事件图谱（当前任务的实体关系/时间线）
│       ├── mcp__knowledge__search_in_memory（server.py:225）
│       │   → 查执行记忆（当前任务的工具执行记录，flow_id 隔离）
│       └── memorist 读 $ROOT_TASK_DIR 文件
│           → 返回历史摘要给领域 agent
│
Step 5: 下次同类任务
│
└── 新任务开始 → Task(searcher) → search_knowledge
    └── 找到 Step 3 存的结论 → 复用 → 加速
```

### 3.2 三层记忆对比

| 维度 | 知识沉淀（knowledge） | 执行记忆（memory） | 事件图谱（events） |
|------|---------------------------|-------------------|------------------|
| **存储后端** | SQLite + sqlite-vec | SQLite + sqlite-vec（同库，doc_type=memory） | Neo4j（Docker `neo4j-events`） |
| **MCP Server** | `knowledge/server.py` | `knowledge/server.py`（`search_in_memory`） | `events/server.py` |
| **数据库文件** | `~/bw-security-analysis/db/knowledge/knowledge.db` | 同左 | Docker 卷 `~/bw-security-analysis/db/events` |
| **隔离** | 全局共享（flow_id=NULL） | 按 flow_id（`db.py:197 WHERE flow_id=?`） | 按 group_id（Graphiti group_ids 参数） |
| **谁写** | 领域 agent 调 `store_knowledge` | 插件 `fireAndForgetMemory`（`security-analysis.ts:720`） | 插件 `fireAndForgetEvent`（`security-analysis.ts:571`） |
| **何时写** | 得出分析结论后 | 每次工具执行后（白名单 `security-analysis.ts:712`） | 每次工具执行 + 每次 LLM 响应 |
| **谁读** | searcher（`search_*`） | memorist（`search_in_memory`） | memorist（events 7 种搜索） |
| **何时读** | 需要确定分析方向时 | 需要回顾当前任务操作时 | 需要查当前任务实体关系时 |
| **查询方式** | BGE-M3 向量 cosine | BGE-M3 向量 cosine | Graphiti 图谱查询（BFS/时间窗口/实体标签） |
| **score 阈值** | 0.2（`db.py:39`） | 0.2（同） | 无（Graphiti 内部控制） |
| **匿名化** | `anonymizer.py`（`server.py` store_* 内调） | `memory_writer_daemon.py` 内置 | Graphiti 内置 |
| **清理时机** | 手动（`clean_databases.py`） | 手动（同左） | session 删除时自动（`security-analysis.ts:620 deleteGraphitiEvents`） |

| **coordinator** | 不直接操作 | 不直接操作 | 不直接操作 |

## 四、技术实现细节

### 4.1 MCP 注册流程

**文件**：`plugins/lib/mcp-manager.ts`

```
plugin.setup（security-analysis.ts:838）

  ↓
mcp-manager.ts:36 registerAll()
  ↓ mcp-manager.ts:43 串行遍历 MCP_SERVERS（行 11-23）
  ↓ mcp-manager.ts:48 registerOne(server, venvPython)
    ├── 不预检测依赖（直接注册，错误从 server 启动 stderr 捕获）
```

## 六、数据清理

**文件**：`.opencode/tools/clean_databases.py`

```bash
# 查看数据量（不删除）
python .opencode/tools/clean_databases.py --dry-run

# 清理两个数据库（需确认）
python .opencode/tools/clean_databases.py

# 只清理 events（Neo4j）
python .opencode/tools/clean_databases.py --events

# 只清理 knowledge（SQLite）
python .opencode/tools/clean_databases.py --knowledge
```

- events 清理：`MATCH (n) DETACH DELETE n` + 删除所有索引和约束
- knowledge 清理：`DELETE FROM answer_vectors` + `DELETE FROM answers`（需先 `sqlite_vec.load(db)` 加载扩展）
- session 删除时 events 自动清理（`security-analysis.ts:1334 deleteGraphitiEvents`）
- knowledge 不自动清理（memory 按 flow_id 隔离，但不会随 session 删除而删除）
