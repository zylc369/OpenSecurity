# 卡壳协议

> 触发条件（满足任一）：同一方向连续失败 ≥5 次；超过 2 小时没有提出新机制假设；准备下"完备 / 不可能 / 已排除"类结论；连续两个"认知检查点"的未测条件栏没有变化。
> 触发后执行以下四步（顺序可按情况调整），全部留痕到分析台账（`$ROOT_TASK_DIR/ledger.md`）。

## 1. 换问题三问（书面）

写下：**"我一直问的是 X（当前问题）；如果真正该问的是 Y，3 个候选：……"** 每个候选再写一句"如果它是真问题，答案大概长什么样"。

例：X = "如何让另一个窗口发消息"；候选 Y = ①何时发消息 ②接收方处于什么状态 ③消息从发出到被读之间经历了什么。

## 2. 换词检索矩阵（外部检索）

列三栏，每栏独立写 3–5 个词，然后跨栏组合成检索词跑 3–5 次检索（searcher 或 websearch）：

| 对象（涉及什么） | 时机（什么时候） | 机制（靠什么原理） |
|---|---|---|
| 例：postMessage / e.source / contentWindow | 例：pagehide / 卸载瞬间 / 导航后 | 例："delivered after navigation" / "message across document swap" |

**禁止用被卡住的当前问题原词去检索**——用旧问题的语言搜不到新答案。

## 3. 无知证书（结构化输出）

把"现在缺什么才能解释现象"写成可检索的条目（而不是继续在旧问题里猜答案）；按固定格式写入台账，区分"知识缺口"与"未想到"：

```text
缺失的概念交集：（要解释当前现象，需要哪几个概念的组合）
需要哪些概念：（逐个列出，2-4 个）
建议检索词：（组合成 3-5 个，交回第 2 步的检索矩阵）
```

连续检索仍无果 = 知识缺口的强信号 → 尽早转求助，停止变体穷举。

## 4. 无记忆评审（派 fresh-eyes）

按 `$OPENCODE_ROOT/agents/fresh-eyes.md` 的输入契约派发（`subagent_type: fresh-eyes`）：

- 输入只有三样：目标 + 原始材料路径 + 分析台账全文（按记录对待，路径见上）。
- **禁带**任何结论、排除清单、"已证明"字样。
- 收到输出后：把"从未被当过变量的维度清单 + 建议实验"写进台账，作为**候选**继续分析：先跑建议实验、按结果更新结论；追加不覆盖。
