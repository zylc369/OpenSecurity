## 知识管理

> **术语约定**：**知识库**专指 `knowledge-base/` 目录下的 MD 文档（权威全文）；**记忆库**专指 events、knowledge MCP 对应的数据库。本文件中的 `search_knowledge`/`store_knowledge` 检索/写入的是**记忆库**，不是知识库文档本身。禁止用"知识库"指代记忆库的任何组件。

分析过程中，遵守以下知识管理规则：

### 查已有知识

**委派 searcher 查**（需要复杂检索策略时）：
- **需要确定分析方向时**：查是否已有同类目标/漏洞/技术的分析记录，避免重复研究。委派 prompt 中描述目标的关键特征（目标类型 + 已知技术特征），让 searcher 能据此构造查询。查到 → 复用已有结论；查不到 → 正常分析。
- **遇到不熟悉的技术时**：查外部资料（CVE 详情、漏洞利用方案、工具文档）。在委派 prompt 中描述遇到的具体问题和上下文。searcher 有 websearch/webfetch 能力。

**直接调 MCP 工具查**（简单检索，不需要委派）：
- **需要操作指引或可复用代码时**：调 `mcp__knowledge__search_knowledge` 查是否已有同类操作步骤/配置方法/可复用代码。查到 → 按已有知识操作；查不到 → 自己摸索。可选传 `lang` 参数按编程语言过滤代码。
- **吸取历史教训**：任务开工或卡壳时，委派 memorist 检索同类历史记录（含失败教训）与未闭环改进项，避免重复已走过的弯路；查到未闭环项先落地再继续分析。同一失败模式第二次出现且对应改进项仍未落地时，无法自行落地的向用户报告，由用户升级到进化流程。

### 存分析结论
- **得出明确分析结论后**（确认漏洞 / 成功绕过 / 还原算法），**必须**存储知识到向量库：
  - `mcp__knowledge__store_knowledge`：存分析结论 / 可复用的操作步骤 / 可复用的 PoC/脚本
  - 代码片段为主的内容传 `lang` 参数标记编程语言
- **入库格式**：结论按"结论三件套"填写（证据等级 + 已验证范围 + 未测清单）；否定/普遍结论缺"未测清单"会被 MCP 校验拒收。

参数填什么、怎么填，参见 MCP 工具的参数描述（调用时自动可见）。
