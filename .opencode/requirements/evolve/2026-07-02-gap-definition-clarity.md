# 需求：明确 gap 定义 + Phase 0 覆盖度强制检查

> 创建: 2026-07-02
> 状态: ✅ 已完成（Phase 2-6 全通过，2026-07-02）
> 来源: R3CTF writeup 调研复盘中，用户指出"gap 不只是方向没有，还包括已有方向覆盖不全"
> 前置: 无（首次改进 evolve 自身的 gap 识别方法论）

## §1 背景与目标

**痛点**: 2026-07-02 R3CTF 往年 writeup 调研中，evolve agent 只识别了"方向级 gap"（Blockchain/Forensics 全空白），漏掉了"技术点级 gap"（已有方向如 Reverse 的 SMC 自修改代码、Pwn 的虚拟机逃逸等覆盖不全）。根因：
1. 入口 C 指引（prompt L254）gap 识别只说"列出知识库中没有的技术"，仅覆盖方向级
2. §5（prompt L133-140）虽提"已沉淀→确认准确完整"，但无可操作检查方法，实际执行时被跳过
3. 无集中的 gap 两维定义

**目标**: 在 evolve prompt 明确 gap = 方向级 + 技术点级两维，并强制 Phase 0 做技术点级覆盖度检查（读内容，禁止靠 grep 关键词判定"已覆盖"）。

**预期收益**（四维度量）:
- 准确度: 避免漏识别已有方向的覆盖度 gap（本次复盘就漏了 nSMC/BabyVM 等）
- 轮次: 未来每次 Phase 0 自动做覆盖度检查，无需用户提醒
- 持续生效: 一次改动，惠及所有后续进化

## §2 技术方案

### 改动性质
- **改 agent prompt**（`.opencode/agents/security-analysis-evolve.md`），2 处局部修改
- 不新增知识库文件、不新增脚本、无架构变更
- 风险等级：中（属"修改 Agent prompt"高风险改动）→ 需端到端验证

### 改动点

**改动点 1: 入口 C 指引（L254）— 明确两维定义**

当前：
```
识别 gap 的方法: 逐篇阅读素材，对照现有知识库索引表，列出"知识库中没有的技术"。
```
改为：
```
识别 gap（两个维度，缺一不可）:
  - 方向级 gap: 某技术领域在整个知识库无对应文件（看目录有无）
  - 技术点级 gap: 已有方向里某技术未覆盖/覆盖不全/不准确（必须读已有知识库内容对照判断，禁止只靠 grep 关键词判定"已覆盖"）
```

**改动点 2: §5 b 点（L136-138）— 补充可操作检查方法**

当前：
```
│    b. 对每条洞察判断: 是否已沉淀到知识库？                     │
│       - 已沉淀 → 确认知识库内容是否准确完整                    │
│       - 未沉淀 → 作为候选方案进入 Phase 1 评估               │
```
改为（拆成两行，适配框图 64 宽，避免破坏 │ 对齐；已测算第1行54宽、第2行49宽，均 ≤64）：
```
│    b. 对每条洞察判断: 是否已沉淀到知识库？                     │
│       - 已沉淀 → 读对应段落对照: 准确？完整？有遗漏？          │
│         不准/不全 → 作为"技术点级 gap"进 Phase 1             │
│       - 未沉淀 → 作为候选方案进入 Phase 1 评估               │
```
