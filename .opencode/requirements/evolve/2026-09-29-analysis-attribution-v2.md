## §1 背景与目标

**来源痛点（实战验证）**：

1. 四行固定结构（自身经验/知识库/记忆库/无记忆评审分身）把"自身经验"变成**残差桶**：运行时恢复（maybeResumeAnalysis）、工作记忆（ledger/压缩）、规范、工具链等未单列机制被静默吸收。初版"自身经验 85%"经纠正重估为"架构 ≈55% / 模型 ≈45%"。
2. 旧命令未要求采集**恢复/检查点事件与硬时序指标**，而该指标是那次归因中唯一的决定性硬证据（恢复注入 00:08:12 → 拿到 flag 137 秒）。
3. 旧命令无**口径**概念（突破口径/体系口径）与**"错过"边际代价**评估，容易把启发式占比读成精算值、把"错过"一律夸大。

**目标**：把上述修正固化进命令本体与 §6.1，使后续归因不再复现同样偏差。

**预期收益（四维）**：准确度显著（分类不偏、证据分层、硬指标优先）；速度持平（取证量相近，指标更有用）；上下文微增（命令 55→77 行，按需触发非常驻）；轮次无变化。

```markdown
## 角色与目标

对**已完成的一次分析任务**做机制贡献归因：按「架构层各机制 + 模型推理」两层统计调用与消费，给出贡献估计（逐项标注口径）、硬时序指标、证据等级与改进线索。只审计、不重做分析、不修改任何文件。

**已知偏差防护（必须遵守）**：
- 不把"自身经验"当残差桶——未单列的机制（运行时恢复、工作记忆、工具链等）必须各占一行或并入架构行；
- 占比是启发式估计（单样本、层间纠缠、不可精确二分），不是精算值；硬指标与主观占比冲突时，以硬指标为准。

**执行权威：本文**（触发、输入解析、取证步骤、输出格式、约束的单一来源）。

## 取证步骤

1. **客观调用计数**（任务目录 `logs/timeline.log` + `logs/plugin.log`）：
   - 记忆库：`knowledge_search_knowledge` / `knowledge_store_knowledge` / `knowledge_search_in_memory` / memorist 派发次数；
   - 知识库：`read`/`grep` 命中 `knowledge-base` 路径的行为（timeline 的 read 条目不含路径 → 用 bash `detail`、`ledger.md`、`progress.md`、产出文档交叉还原；无法还原时标注"计数不完整"）；
   - 子 agent：task 派发对象（searcher / memorist / fresh-eyes / knowledge-scout）；
   - 其他分析工具调用（环境相关，如 idat）；
   - **恢复/持续机制**：`session.idle`、`恢复消息已发送`、`检测到完成标记`、`跳过恢复 — 开关已禁用`、`认知检查点` 注入的计数与时序；记录**注入 → 完成（或完成标记）间隔**（硬指标）；
   - 配置核对：相关 agent 的 frontmatter、片段挂载、工具权限（解释某机制"没有调用"的工具侧原因）。
2. **落库状态核对（区分"没有/错过"）**：
   - 直读 `$OPENSECURITY_HOME/db/knowledge/knowledge.db`：`answers` 表按关键词/时间查条目、`answer_vectors_rowids` 查向量索引状态；
   - 直读仅用于存储/索引状态审计；**检索质量复测必须走真实检索路径**——派发 memorist 用目标关键词（英文标识符原样）复测，要求逐字返回 id + question，**禁止直查数据库/按 id 反查代答**（否则测的不是检索本身）；命中 → 原调用属检索时机/关键词问题，未命中 → 查存储与向量索引状态；无权限/不可用时标注"未复测"并列入遗留。
3. **消费质量归因**：读 `ledger.md`/`progress.md`/产出文档与日志时间线，判断各调用是否真正支撑关键步骤/突破；无法判断的条目标注"需自述"；对每次"错过"评估**边际代价**（若当时被消费，是否真会改变结果/节省多少）——防止把"错过"一律记成重大损失。
4. **自述补充**：当前会话包含分析上下文时，基于会话自述突破归因；不含时标注"自述缺失"，仅给日志侧结论。

## 输出格式

1. **机制贡献表（两层结构；"自身经验"不得作为残差桶）**

   架构层建议行（无事件的记 0 并给零证据）：运行时持续性与恢复 ｜ 工作记忆与上下文管理（ledger/压缩/持久化） ｜ 规范与方法论（prompt/片段/检查点） ｜ 子 agent（派发与产出） ｜ 知识库·记忆库·MCP ｜ 工具链。
   模型层单行：模型在架构内的推理（"自身经验"仅指上下文内新增推理：假设、实验设计、组合、验证）。

   | 机制 | 调用/事件计数（含硬指标） | 有效消费项 | 贡献（估计；标注口径） | 证据等级 |
   |------|--------------------------|-----------|----------------------|---------|

   - **口径**：突破口径只算对最终结果（解出/完成）的直接因果贡献；体系口径计流程/防错/沉淀价值。每个数字标注口径。
   - 表尾给出两层合计（架构 ≈X% / 模型 ≈Y%；难以合计时用区间表述），并注明"启发式估计、单样本、不可精确二分"。

2. **硬时序指标**（优先于主观占比；不可得标"不可得"）

   | 指标 | 值 |
   |------|----|
   | 恢复注入次数；注入 → 完成（或完成标记）间隔 | |
   | `session.idle` 次数与跳过原因分布 | |
   | 上下文压缩次数（可得时） | |
   | 人工消息次数 | |
   | 检查点注入次数（可得时） | |

3. **知识消费明细**（可选）：| 来源（KB 文件/记忆条目 id） | 命中方式 | 是否被消费 | 支撑了哪一步 |

4. **没有 / 错过 清单**：| 项 | 判定 | 依据 | 错过边际代价（估） | 修复方向 |

5. **结论**：两层贡献（启发式估计）+ 置信度 + caveat（回溯归因主观、单样本无法消融、口径逐项标注、硬指标优先）；发现的缺口列候选改进线索（交进化流程评估，不在此实施）。

## 约束

- 只读审计：不修改任何文件、不写知识库/记忆库；
- 不重做分析、不评价分析结论对错（只归因机制贡献）；
- 数字可追溯：任何占比/计数必须能指回日志或取证记录；无法量化的推断标注"需自述/不可得"；
- 路径引用保持 `$OPENCODE_ROOT`/`$TASK_DIR`/`~` 形式，禁止硬编码绝对路径；
- 任务目录与知识库 DB 位于数据主目录（`$OPENSECURITY_HOME`）——该变量由 Plugin 注入（见环境信息段）；交互会话遇外部目录权限询问时放行只读访问（非交互运行需预授权）；
- 日志缺失时降级：标注"降级模式（无任务目录日志）"，仅用产出物 + 自述归因并降低证据等级。
```
