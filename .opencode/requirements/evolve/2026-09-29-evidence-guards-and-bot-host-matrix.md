## §1 背景与目标

**来源痛点（复盘数据）**：

1. 主机形态矩阵实验经外部 302 包装提交，四种形态全落登录页 → "机器人无会话"被记为观测结论并固化 → 真正的变量（宿主形态 × 自带会话）被排除约 24h；直接提交复核后 137 秒解出。
2. 共享基础设施（另一题组件）中"哈希可验证的密码"被当作本题线索，消耗约 10-15h、上万次尝试。
3. 决定性技法（bot 自带会话检测、锚点 + 视口配合）仅存于记忆条目，知识库零覆盖，同类题将重复探索。
4. 卡壳期历史检索（memorist）零派发；任务内新落库条目在终解前未被回检（次要）。

**目标（四条）**：

- ① "负面/零结果结论"必须写明观测方式，单路径负面结论不得作为"已排除"前提（execution-discipline 认知纪律增补）；
- ② "高价值线索"先做归属验证（①、②都答"不"）→ 标注来源存疑并降级（evidence-discipline 增补）；

- ④ stuck-protocol 第 2 步检索渠道补本地通道（技法词直查记忆库 + memorist）。

**预期收益（四维）**：准确度显著（阻断假阴性→假公理链；防诱饵锚定）；速度显著（同类场景 10h+ 级止损）；上下文：常驻片段净 +2 行；轮次：无新增往返。

```
### 3.5 渲染/截图类 Bot 的自带会话与宿主形态矩阵

**何时查本节**（满足其一即读）：
- 提交 URL 后由 bot 访问并回传截图/渲染结果（视口截图类功能）；
- 目标系统存在登录态与分级权限（personnel/clearance、role、admin 等字样），或存在"等级不足则隐藏/遮蔽（REDACTED）"的区域；
- 已确认 bot 可访问本机/内网地址，需要判断"bot 以什么身份访问"。

**核心假设（先测再排除）**：渲染 bot 往往在自身环境里登录过目标站（账号常是系统自述的自动化角色：巡检、审核、代理）。检测方法 = 宿主形态矩阵对照实验：

| 步骤 | 做法 | 判据 |
|---|---|---|
| 1. 选路径 | 选"仅登录后可见"的页面（如档案/控制台） | 未登录应得登录页/302 |
| 2. 换宿主形态 | 同一路径用不同宿主形态逐一提交：`127.0.0.1` / `localhost` / `localhost.`（尾点）/ `[::1]` / 容器服务名 / 站内域名 | 逐形态对照返回内容 |
| 3. 直接提交 | 每个形态都**直接**把 URL 提交给 bot；不得经外部跳转/短链 302 包装 | 包装提交与直接提交的观测结果可能不同（包装提交可能不携带会话）；"无会话"的排除性结论必须以直接提交复核 |
| 4. 判读 | 某形态返回已登录内容、其它形态返回登录页 | bot 会话绑定在该宿主形态上（cookie 按 host 隔离） |

**利用链（已知绑定形态后）**：
1. 用绑定形态访问 bot 自己的档案/资料页；
2. 视口截图类 bot：目标区在折叠线以下时，在 URL 追加 `#<元素id>` 片段锚点，让浏览器滚动到该区再截图（片段只由浏览器处理）；
3. bot 账号即特权账号（页面自述自动化/巡检角色）时，档案受限区可直接读取。

**排错**：
- 全形态都落登录页：确认提交未经过包装；确认路径为"仅登录后可见"；用其它登录可见页复测；
- 仅部分形态命中：属预期（会话只挂一个宿主形态）；同时记录该形态是否也是地址过滤器的放行形态（两件事常在同一形态上耦合）。

**防御侧反推**：截图/渲染 bot 不应携带任何登录态；必须登录时用与用户导航上下文隔离的专用低权限会话。
```
