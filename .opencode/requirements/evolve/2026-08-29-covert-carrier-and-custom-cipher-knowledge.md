# 需求：隐蔽载体解码与自制密码结构分析知识沉淀

## §1 背景与目标

**来源**：COMPFEST 镜像对抗训练复盘（2026-08-29 会话，《复盘报告》痛点 1/2 + 洞察 1-9）。

**痛点**：
1. 载体排序知识缺失（同日多内容按错误序拼接）导致解码串 60% 后段错误，在错误结果上消耗 ~2 小时无效探测；且源文本中"顺序不保证"的元提示被读到但未触发怀疑
2. 自制分组密码的结构化攻击（积分攻击）经验仅存于记忆库单条记录，知识库无对应文件，下次遇到需重走完整摸索路径
3. 编码参数自检纪律（"部分解对 ≠ 全对"）未沉淀

**预期收益**（四维度量）：
- 减少上下文：同类任务直接路由到知识文件，省 10-15 轮摸索（本次实测浪费 ~20 轮）
- 减少轮次：载体判存指纹表避免逐平台试错（本次 ~15 次无效平台探测）
- 提升速度：积分攻击模板 + 工程坑清单避免 457 秒级失败重试
- 提升准确度：排序坑与自检纪律直接命中本次最大失误模式

**硬约束（用户要求）：通用化措辞**。所有新增内容禁止出现训练场景术语（赛事/比赛/题目/flag/出题人/解题/writeup 等），统一替换为通用安全研究术语：

| 禁用 | 替换为 |
|------|--------|
| 赛事/比赛/CTF | 对抗训练/分析任务（尽量不提） |
| 题目/出题人 | 目标样本/构造者 |
| flag | 目标数据/待恢复秘密 |
| 解题/solve | 恢复/还原 |
| OSINT 题 | 公开载体调查 |

理由：知识库读者是 AI，训练场景措辞会让知识只在比赛语境激活；同等技术在协议逆向、样本分析、数据取证中通用，必须以通用形态沉淀。已有的 `crypto-methodology.md` 中存量措辞不在本次修改范围。

### 2.2 文件 1 内容大纲：`custom-cipher-structural-attacks.md`

标题定位：自制分组密码的结构分析与积分攻击——拿到完整源码 + 大量选择明文密文记录时的还原路径。

1. **触发场景**：样本提供自制分组密码完整源码（非标准 AES/DES）、大批量结构化 (明文, 密文) 记录、一个待解密的认证加密盒
2. **轮函数组件弱点清单**（每组件：什么结构暴露什么攻击面）：
   - Feistel 半字节 S 盒（`l ^ F(r)` 型）：半交换结构、无高阶扩散
   - 全局位仿射置换（`i → (a*i+b) mod n` 型）：可编程求逆，非混淆
   - 逐字节独立最终层（矩阵+常数 XOR）：per-byte 攻击面分离
   - 轮密钥派生只依赖主密钥高位子集：高低位分离攻击
3. **积分攻击完整流程**（本次实例的通用化模板）：
   - 前提识别：记录集是仿射子空间枚举（JSON 中 `base`/`basis`/按位选择枚举描述）
   - 平衡性验证：自造密钥本地实验确认 N 轮后逐字节 XOR 和为 0（先实验后攻击）
   - 逐字节枚举过滤（4096 矩阵索引 × 256 常数，`np.bitwise_xor.reduce` 向量化，实测 13 秒）
   - 唯一化后正向回推：轮密钥已知 → 中间态 → 剩余密钥位直接解出
   - 多记录集联合过滤（2 候选 → 加 set 消歧）
4. **工程坑**：
   - GF(2) 矩阵求逆：增广单位阵必须放 bit 8-15（放 bit 0-7 污染系数区，症状：rank 报 8 但求逆失败）
   - 攻击先在自造密钥上端到端验证再打真实数据
5. **认证加密盒开启**：HMAC 认证 + sha256 密钥流的标准结构，密钥恢复后直接调用样本自带解密函数

### 2.3 文件 2 内容大纲：`covert-carrier-decoding.md`

标题定位：隐蔽载体定位与多级解码——目标线索仅一个句柄（handle）时，从公开平台内容到密码学负载的完整调查链。

1. **触发场景**：目标仅给 `@handle` 或一个词组，需从公开平台内容中提取隐藏编码
2. **平台判存指纹表**（本次实测，避免逐个试错）：
   - Instagram：`/用户名/embed/` 真实账号 ≈620KB、不存在 ≈217KB 模板；Googlebot UA 直抓帖子页（含评论正文）；`/p/<code>/media/?size=l` 取 1080px 原图；无头浏览器渲染主页可得 bio/帖子网格/caption
   - Telegram：`t.me/<name>` 的 `og:title`，"Contact @xxx" 模板 = 不存在
   - 自建短链：未知 slug → 307 跳转 /404；有效 slug → 302 目标
   - 通用：og:title/字节数指纹判别软 200
3. **文本载体编码识别**（解码实现收口至 `classical-crypto.md` §6 唯一维护点，本文件只留识别信号 + bit 串生产职责 + 引用——见下方"结构修复记录"）：
   - 首字母双符号收敛（如仅 Old/Only vs Books/Beneath/Before/Between/Broken/Beyond 两类）→ Bacon 型识别信号
   - 字母表外字符提示（"beyond Z"类元话语 = base32 数字 2-7 扩展）
   - 分隔符数字（2/3 等独癧行字符 = 断句符，拆分后拼出 域名/路径）
   - 重复行/异常行 = 构造者的元提示，必须显式消化
4. **多级链标准流程**：句柄 → 平台判存 → 内容抓取 → 编码识别与解码 → 中间串语义断句 → 资源定位 → 密码学负载
5. **解码自检三问**（方法论纪律，与 §2.4 联动）：
   ① 解出部分有意义内容时，无意义部分是否在提示参数（顺序/对齐/映射）错误？
   ② 源文本中被忽略的元提示（顺序/缺失/分隔/表外字符/重复）有哪些？
   ③ 结果用不通时，先回头怀疑解码参数，再扩大结果使用面
6. **时间戳排序坑**（本次最大失误的通用化）：
   - 同日多条内容排序：短码是 base64url 字母表（A-Z < a-z < 0-9 < - < _），非 ASCII 字典序（`3`(0x33) < `c`(0x63) 在两套序中结论相反）
   - 部分正确 ≠ 全部正确：前段解出有意义词（如组织名）只证明该段对齐正确，不外推全串
   - 具体校验代码：base64url 序比较函数
