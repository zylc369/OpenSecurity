# 需求文档：分段器 v2（阶梯 / 尾并回阈值 / 软标点断 / 硬结束）

> 状态: Phase 2 草稿
> 来源: 2026-10-18 试听段间断档复盘（98 字文案切 [17,81]，81 字段生成 11.1s > 段1 窗口 9.8s）→ 用户定稿完整规则集

---

## §1 背景与目标

### 1.1 背景

1. 实测断档（11:08 轮）：默认文案被切 `[17,81]`（81 = 46+35"尾并回"产物），段2 从请求到可用 14.2s > 段1 窗口（生成 5.7 + 播放 4.1）9.8s → 断档 ≈4.4s。
2. 机制核查（代码 + node 执行）：段长超标三来源——句块不可劈（跨目标整吞）、预检例外（小段头+大句可到 159）、尾并回（小尾并入前段）。
3. 分段器只在前端（`frontend/src/utils/segmentText.ts`；后端仅 `MAX_TEXT_LEN=2000` 校验——grep 验证服务端零分段逻辑）。

### 1.2 目标（用户定稿规则集）

| # | 规则 | 定义 |
|---|------|------|
| G1 | **阶梯渐进分段** | 默认 `[20,40,60,80]`，前端可配置；常规段=末档（80）封顶 |
| G2 | **尾并回阈值 = 首段分段字数**（动态） | 尾段 `< 首段值`（默认20）→ 并入前段；`>=` → 独立；保留"合并后 ≤ max(目标×2,160)"上限 |
| G3 | **超软阈值 → 软标点断** | 软阈值 = 当段目标 + 首段值；**软标点** `{，、；：,;:}`；超阈值后遇到**软标点**即断；数字间 `:`/`,`（如 12:30、1,000）防误切（与小数点同款） |
| G4 | **超硬阈值 → 硬结束** | 硬阈值 = **（首段×2）+ 当段目标**（默认 40+goal）；超过该值**直接在当前位切分，不管韵律、通顺** |
| G5 | **硬标点正常收段** | 硬标点 = `。！？…!?\n`（小数点防误切）+ 数字间冒号/逗号防误切——**原逻辑不变**；收尾符（闭引号等）并入不变 |
| G6 | **两套实现同步** | `segmentText`（全量）与 `createSegmentFeeder`（惰性）逐段一致（等价性测试为证） |

### 1.3 非目标

- 服务端零改动（已核实分段只在前端）
- 不做"首段优先调度"（C1/C2；C2 已收回）
- 不改"句末标点+收尾符"、"小数点防误切"等既有防线
- 不改变"硬标点收段时整句不劈"的默认行为（软/硬断仅为**超限**时的守门）

## §2 技术方案

### 2.1 `segmentText.ts` 核心改动

**常量与集合**：

```ts
const SOFT_PUNCT = new Set(["，", "、", "；", "：", ",", ";", ":"]);
// 数字间防误切: 与小数点同款——前后皆数字则跳过（半角 ":"/"," 与全角 "：" 一并防御，如 12:30、1,000、12：30）
// 阶梯默认 [20,40,60,80] 由 rampFor(20, 80) 派生——不新增独立常量
```

**`rampFor(firstLen, target)` 改梯形派生**：

```
[f, min(2f,target), min(3f,target), …, target]（去重、升序、末档恒为 target）
f=20,target=80 → [20,40,60,80] ✓；f=30,target=80 → [30,60,80]
```

**扫描逻辑（超限守门，全量版第二遍与 feeder 主循环同步）**：

以"当段目标 goal、首段 first"计：
```
软限 softLimit = goal + first
硬限 hardLimit = 2*first + goal

处理句块 p（不可劈的最小源单元，软/硬断可再分）:
  if cur + p <= softLimit:            # 正常区
      cur += p; cur >= goal 时正常收段
  else:                               # 超软限
      # ① 尝试软断: 在 p 中自 "softLimit-cur" 位置起、至多到 "hardLimit-cur"，
      #    找第一个软标点（数字间 : , 防误切）
      #    ——软标点若超出硬限位置 → 视为未找到
      # ①b 回落（实施期实测补充——防整吞长段）: ①未找到时，取"本片内、超限点
      #    之前"最近的软标点（宁可略早断，保段长受控）
      if ①找到软标点位置 c 且 c <= hardLimit - cur.length（或 ①b 回落找到）:
          收段(cur + p[:c]); p = p[c:]; cur = ""
          （对剩余 p 继续循环——可能再触发）
      else:
          # ② 无软标点: 超硬限则硬结束，否则整吞（等后续句/涨到硬限）
          if cur + p > hardLimit:
              收段(cur + p[:hardLimit-cur]); p = p[hardLimit-cur:]; cur = ""
              （剩余继续循环）
          else:
              cur += p（整吞——延续无标点长文场景）
```

**尾并回**（`finishTail` 与全量版收尾同步）：
```
阈值: firstTargets[0]（首段值，动态；原 target*0.5）
条件: tail.length < 首段值 && prev + tail <= max(target*2, 160) → 并入 prev
否则: tail 独立成段
```

**预检收段（保留）**：既有"`cur >= 半目标 && 吞下句超 1.5×目标 → 先收`"逻辑**保留**，
与软/硬守门**互补**（预检管"大 cur + 大句"的拖拽，守门管"累计超限"的切分）；
二者共存时以"先预检、后守门"的顺序执行（预检不触发才走守门判定）。

**splitOversize 处置**：保留原实现（单句 > hm 的既有防线）；新增守门逻辑生效后其逗号兜底职责重叠——**实施时以"新逻辑覆盖 + 保留既有兜底"为准，避免行为回退**（二者互不冲突：新逻辑在"累计"维度，splitOversize 在"单句"维度）。

### 2.2 `useTtsPlayer.ts` 参数链路

- `StartOptions` 新增 `stairs?: number[]`（阶梯序列，**优先**）
- `firstTargets = normalize(opt.stairs) || rampFor(firstLen ?? 20, nextLen ?? 80)`
- 规范化：正整数、长度 1..8、升序去重、末档即"常规段"；非法回退默认
- 保留 `firstLen`/`nextLen`（兼容其它调用方/测试）

### 2.3 `TtsSection.tsx`（UI）

- "分段设置（字）"：两个 InputNumber（首段/常规段）→ **阶梯输入**（文本框，默认 `20,40,60,80`，逗号分隔可编辑）
- 解析校验：非法（空/非数字/无正数）→ 回退默认 `[20,40,60,80]`；界面提示末档=常规段
- `player.start(text, { ..., stairs })` 传递
- `TtsSection` 的 `firstLen`/`nextLen` state 由 `stairs` state 取代（实施时检查全部引用；"刷新是否保留设置"与现状一致=不持久化，非本批目标）
