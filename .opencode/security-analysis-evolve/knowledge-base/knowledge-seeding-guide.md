# 知识库 Seed 操作规范

> 将 .md 知识库文件中的技术知识提炼并存入 knowledge MCP 向量数据库时，必须遵守本规范。
> 本规范基于两轮质量验证的实战经验总结。

## 核心原则

1. **读完整全文再提炼**——禁止只读前 50-80 行就提炼。每个文件从头到尾读完，理解全部内容后再判断有哪些独立技术点。
2. **不为提炼而提炼**——只提取可复用的独立技术知识（攻击方法、工具用法、识别模式、代码模板）。流程描述、行为规则、编码规范不提取。
3. **每条知识自包含**——不引用源文件路径（禁止"详见 xxx.md"）。被引用的内容要么内联到当前条目，要么单独建一条知识供检索。
4. **question 从"谁会搜、怎么搜"角度写**——包含该知识点独有的技术关键词，便于语义搜索匹配。

## 提炼流程

### Step 1：读取完整文件
用 Read 工具读取目标 .md 文件的**全部内容**。不跳过任何章节。

### Step 2：识别独立技术点
逐个章节（## 级别）检查：
- 该章节是否包含**可复用的技术知识**（攻击方法 + 条件 + 代码/步骤）？
  - 是 → 提取为独立知识条目
  - 否（纯流程描述/行为规则） → 跳过
- 相邻章节的同类知识是否应该**合并**为一条？
  - 如果一个章节内容很少（如 Boneh-Durfee 只有 3 行描述），合并到相邻的主条目中
  - 如果一个章节内容很丰富（如 Smart 攻击有完整代码），独立成条

### Step 3：构造 question + content

**question 构造规则**：
- 用中文自然问句
- 包含该知识点独有的技术关键词（如 anomalous、p-adic、delegatecall、PTR_MANGLE）
- 避免与同类知识的 question 高度重叠（如果两条知识 question 关键词 70%+ 相同，会导致检索竞争）
- 格式示例：`RSA 小公钥指数开方攻击怎么做 e=3`

**content 构造规则**：
- 包含完整的适用条件（什么时候用）
- 包含可操作的步骤或代码（怎么做）
- 包含验证方法（怎么确认做对了）
- 代码片段必须完整可执行（不能只有片段）
- **禁止引用源文件**——不写"详见 xxx.md"、"转 xxx.md"、"xxx.md 补充"。如果需要引用其他知识，要么内联关键内容，要么用"见相关知识"这种知识库内部引用（不指向文件路径）
- 英文技术标识符原样保留（CVE 编号、函数名、payload、命令）

**lang 参数**：
- content 含代码且代码是核心知识时传 lang（python/sage/bash/javascript/solidity）
- 纯文字知识不传 lang

### Step 4：入库
调用 `knowledge_store_knowledge(question=..., content=..., lang=..., message="seed：来源文件名")`

## 质量验证框架（8 维度）

完成一批文件的知识入库后，必须执行质量验证。建议用独立子任务（Task 工具）执行，避免"自己写自己审"的偏差。

### 维度 1：文件覆盖度
拿完整文件清单（排除 knowledge-writing-guide/script-generation/opencode-*/knowledge-sourcing-guide），逐个检查是否已处理。

### 维度 2：章节覆盖度
对每个已处理文件，列出所有 ## 章节，检查每个含技术内容的章节是否被至少 1 条知识覆盖。

### 维度 3：检索 Recall
对每条知识，构造"未来 agent 会怎么搜"的查询，调 `knowledge_search_knowledge` 验证目标条目在 top-5 中。

### 维度 4：检索 Precision
用跨领域查询搜索，检查 top-5 中是否有明显的跨领域误匹配。
- 如果某领域的条目频繁误入其他领域的搜索结果，考虑在 content 开头加领域限定语（如"仅适用于 Solidity/EVM 智能合约场景"）

### 维度 5：内容准确性
随机抽 5 条，重新读源文件对应段落，对比 content 是否有遗漏或错误。

### 维度 6：Question 质量
检查 question 是否自解释、关键词是否丰富、与同类知识是否有区分度。

### 维度 7：内容自包含性
扫描所有条目的 content，检查是否有源文件引用（"xxx.md"、"详见"、"转"）。发现则修复——内联被引用的内容。

### 维度 8：无重复
检查是否有两条知识的 content 高度重叠（>70%）。发现则拆分职责或合并。

## 常见错误（基于实战验证总结）

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| 只读前 50-80 行就提炼 | 遗漏后半部分的知识 | 读完整文件全文 |
| content 含"详见 xxx.md" | 检索到该条目时无法获得被引用内容 | 内联关键内容，去掉文件引用 |
| question 与同类知识高度重叠 | 检索时互相竞争，可能被挤出 top-5 | 强化独有关键词（如 anomalous/p-adic） |
| 代码片段不完整 | agent 无法直接执行 | 包含完整可执行代码 |
| 领域不限定 | 跨领域搜索误匹配 | content 开头加领域限定语 |
| 两条知识内容重叠 >40% | 检索结果冗余 | 拆分职责，各管一方面 |
