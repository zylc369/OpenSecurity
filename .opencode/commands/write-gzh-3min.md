## 角色与目标

把安全分析过程、CTF 解题经历或技术主题，加工成公众号 **【有趣的技术3分钟】** 栏目文章：面向有技术背景的大众读者，3 分钟读完，有故事、有反转、有带走价值的原则。

**边界**：写科普文章，不写 writeup（writeup 走 `write-writeup` 命令，面向安全初学者、追求完整复现；本命令面向大众、追求"有趣 + 一条原则"）。

## 输入（$ARGUMENTS）

- 素材来源（三选一或多选）：
  - 一次解题/分析会话（对话上下文）
  - 分析文档 / writeup 路径
  - 一个裸技术主题
- （可选）用户指定的侧重角度

$ARGUMENTS

## 输出

- 文章：`docs/公众号文章/【有趣的技术3分钟】<标题>.md`
- 文件名去掉逗号/引号等标点（只保留中文、字母数字、连字符），正文标题保留完整标点

## 选题快评（先判断再动笔）

好题材三要素（至少满足两个，否则向用户建议换题）：

| 要素 | 说明 | 本栏目实例 |
|------|------|-----------|
| **认知反转** | "看起来 X，其实 Y"——吓人的东西是弱点 / 防御本身是算法 | 6000 位大数公钥其实是致命伤；"反调试"其实就是校验算法 |
| **祖传技术的新马甲** | 老技术/老攻击换场景复用，年代感制造反差 | 1990 年 Wiener 攻击通杀 2026 年多项式 RSA |
| **可类比性** | 核心概念能用生活类比讲清（时钟、最简分数、快递……） | 商环=带物理定律的小宇宙；连分数=355/113 逼近 π |

## 硬性规则（防翻车清单）

| # | 规则 | 说明 |
|---|------|------|
| 1 | **现役比赛禁发标注** | 素材来自**进行中**的 CTF → 文首必须加 blockquote：发布不得早于比赛结束时间（查赛事页面，换算成北京时间 UTC+8） |
| 2 | **敏感信息三不** | 队伍账号/密码、token、进行中比赛的服务器地址（nc/IP）绝不进文章；题目公开数据（页面可见的 N/e/密文）可用 |
| 3 | **数字必须可溯源** | 位数/耗时/概率/次数等全部数字逐条对照素材原文，禁止编造或"差不多" |
| 4 | **类比先行的同时保精确** | 每个技术概念先类比后精确定义，类比不得扭曲数学本质（讲完类比马上给严格表述） |
| 5 | **裁剪纪律** | 3 分钟 ≈ ≤200 行。只留主线 + 至多一个彩蛋；专家级细节（界分析/备选攻击/推导）直接砍掉，不留残句 |
| 6 | **点名出处** | 栏目惯例点名来源挑战（比赛名 + 题名），前提是已结束或已加禁发标注 |
| 7 | **公众号排版友好** | 少用表格（渲染不稳）；代码块短小（≤8 行）且仅为佐证氛围，不承担教学任务 |

## 栏目风格规范

```
1. 标题：【有趣的技术3分钟】+ 悬念式命题（"一道 X 的题，死于 Y" / "如何藏 X"）
2. 引子 blockquote：2-3 行，反差/悬念，直接抛结论的另一半
3. 开篇场景钩子：第一人称进入故事的瞬间（连上服务器看到什么/打开文件看到什么）
4. 分幕推进（3-4 幕）：每幕 = 一个知识点 + 一个小反转；幕标题口语化（"第一幕：……"）
5. （如有）彩蛋幕：解出之后还要再考一次的二次反转
6. 结尾升华：超出本题的通用原则（防御视角/工程方法论），1-2 条
7. 金句收尾：一行以内的 zinger（"老酒从不退场，只是换了瓶子"级别）
```

真实翻车经历（推演半小时输给 0.2 秒实验之类）是好素材，如实写进对应幕——自嘲是栏目的调味料，但必须真实（规则 3）。

## 执行流程

1. **对齐风格**：读 `docs/公众号文章/` 下至少一篇现有文章（Glob 现有文件）
2. **提取素材**：故事弧（反转点在哪）、关键数字、可用类比、真实翻车点、比赛结束时间（如涉现役比赛，查赛事页面确认）
3. **选题快评**：三要素对照，不足两个 → 向用户建议换题并说明原因
4. **定标题**：给用户 2-3 个候选（含前缀）；用户未选时取自认最强的一个并说明
5. **成文**：按栏目结构一次 Write（≤200 行；超过则拆两次 Edit）
6. **自检**：对照下方清单逐项过，发现问题立即修

- [ ] 所有数字与素材一致（逐条核对过）？
- [ ] 每个技术概念先类比后精确定义？
- [ ] 有认知反转 + 结尾升华 + 金句收尾？
