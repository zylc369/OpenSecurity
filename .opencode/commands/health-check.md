## 这个命令做什么

对 OpenSecurity 项目做体检：按下面给出的检查方向，自行构造并执行检查命令，产出分级报告。

- **静态健康**（A 层）和**运行时健康**（B 层）：每次全做
- **增量检查**：分析近期迭代，找出下面方向未覆盖的新组件，现场设计检查并执行

每项检查自行设定通过标准（如：零报错、数量相等、命令可用），达到即通过，不与历史体检结果对比。

`$ARGUMENTS` 可传指定关注面（如 `只查运行时`）。空 = A+B 全做。

## 执行流程

### 第 1 步：增量检查

1. 收集近期改动信息（有几条用几条）：
   - `git status --short`
   - 当前对话上下文
2. 找出新增的、下面两个方向未覆盖的组件
3. 对每个新组件：现场设计检查并执行，结果计入报告（只在本次有效，不写入任何文件）

### 第 2 步：静态健康（A 层）

检查方向，自行构造命令：

| 方向 | 通过标准 |
|---|---|
| 代码可编译：`.opencode/control/backend` 和 `.opencode/mcp-servers` 的 .py、`.opencode/plugins` 的 .ts | 语法检查零报错 |
| 禁止项零残留：安装引导里的 brew、知识库/agent 对 docs/ 的运行时引用（download_sources 例外条款除外）、近期重命名的旧标识 | grep 零命中 |
| git 工作区状态可解释 | `git status --short` 逐条定性：合法待提交 / 放错位置的运行时产物 / 未知来源（🔴） |
| 命令目录卫生 | `.opencode/commands/` 只有 *.md 和命令配套目录 |

### 第 3 步：运行时健康（B 层）

检查方向，自行构造命令。socket = `~/bw-security-analysis/opensecurity-control.sock`。

| 方向 | 通过标准 |
|---|---|
| 控制台后端：system 接口响应 | 正常返回且 `code_stale=false` |
| API 数据一致：scan 与 deps 接口 | 两者读同一份工具清单，工具数量相等 |
| 环境注入：在 bash 工具里实测 | PATH 前两前缀 = venv/bin、工具 bin; `$WORDLISTS_DIR` 非空 |
| MCP：全部 server 注册 | 对照实际清单（mcp-servers/ 目录），注册日志无失败 |
| 错误日志：当前 agent 的分流日志（`~/bw-security-analysis/logs/<agent>.log`，非 plugin_debug.log） | 无新增 ERROR/WARN |
| 工具抽验：从工具 bin 目录抽 3 个直接运行——1 个本机二进制、1 个容器 wrapper、1 个近期新增的 | 都能执行（如输出版本号） |
| 数据落点健康：近期记忆库沉淀可召回（无新沉淀则跳过）; db/logs 体积无异常（参考阈值: db > 2GB、logs > 500MB 记 🟡） | 按上述标准 |

### 第 4 步：报告

```
## 体检报告（静态 N 项 + 运行时 M 项 + 增量 K 项，增量来源: <...>）
| 层 | 项 | 结果 | 说明 |
✅ 通过 / 🟡 观察项（不影响功能，报告待用户决策）/ 🔴 异常项（必须处理）
增量检查项: 逐条列出第 1 步执行的检查
```

🔴 项：立即修复，报告中记录修复动作和重验结果。

### 第 5 步：体检完成后，判断是否更新本命令

逐条复查第 1 步的增量检查：

- **固化条件**：该组件长期存在（非一次性试验），且它的检查方法下次体检还会用到
- 满足条件：用 Edit 把检查方向插入 A/B 对应表的最后一行，行尾标注 `(+ YYYY-MM-DD <来源>)`
- 不满足：只在本次报告中留记录，不改本命令

报告末尾注明结论：`本命令已更新: 新增 N 项（列出）` 或 `本命令无需更新: <原因>`。
