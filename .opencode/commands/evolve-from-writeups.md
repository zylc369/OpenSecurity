## 角色与目标

触发"从信源学习"的进化流程（evolve agent Phase 0 入口 C 的命令化封装）。

**本命令是薄触发器**：只做输入解析 → 派发 → 呈现报告三件事。进化的方法论（gap 两维判定、价值判断、知识编写规范、沉淀流程）收口在 security-analysis-evolve agent 系统提示 + sourcing-guide 中，此处禁止重复。

## 输入解析（$ARGUMENTS）

| $ARGUMENTS 值 | 行为 |
|---------------|------|
| 空字符串（用户调用 `/evolve-from-writeups` 未带参数） | **默认全方向**：同 `all`，并行派发 6 个子任务（方向为本表"方向名"行列举的六个，每方向一个独立 task，用下方同一模板），全部完成后汇总成总表呈现 |
| `all` | 同上（显式写法） |
| 方向名（`binary` / `mobile` / `web` / `crypto` / `ai-security` / `forensics` 之一——本项目知识库的六个组织维度，非安全领域全集） | 限定该方向的知识库做 gap 对照 |
| URL | 直接从该信源页开始扫描（跳过信源选择步骤） |
| 其他文本 | 原样作为扫描主题传给 evolve agent。**不限于六方向**——OSINT、AD/域渗透、云安全、工控、无线等任何安全主题都走此路径，由 evolve agent 按主题自行映射信源和知识库对照 |

$ARGUMENTS

## 执行：派发

用 task 工具派发给 `security-analysis-evolve` agent，派发 prompt 用下方模板（替换 `<输入>` 为解析后的值）：

```
任务: 从 writeup 信源扫描并进化知识库（你的 Phase 0 入口 C，走完整流程）。

输入: <输入>

时间范围: 只扫最近 90 天内发布的 writeup（按信源页面标注的发布日期筛；页面无日期的条目保守起见视为超期跳过）。用户明确指定了其他范围则以用户为准。

执行要求:
1. 信源选择、扫描方法、价值判断标准唯一权威是
   $AGENT_DIR/knowledge-base/knowledge-sourcing-guide.md（§1 信源表 + CTF Base 关键词映射 + §3 价值判断），不重复造轮子
2. 按输入映射信源，扫描获取 10-20 篇候选（标题+摘要级浏览，webfetch 不保存）
3. gap 两维判定逐篇执行: 必须读对应方向知识库的实际内容对照判定，
   禁止只看索引或 grep 关键词就判"已覆盖"
   - 方向级 gap: 该技术领域在整个知识库无对应文件
   - 技术点级 gap: 已有文件里该技术未覆盖/覆盖不全/不准确
4. 高价值项下载保存到 SOURCE_DIR（download_sources.py 或指南 §2 方法），深读上限 5 篇（上下文保护）
5. 沉淀前必读 $SHARED_DIR/knowledge-base/knowledge-writing-guide.md，遵守全部规范
6. 沉淀产物只写"什么场景、怎么检查、怎么利用"，不写经验来源、不按时间线叙述
7. 如果发现的 gap 属于脚本/prompt/架构级改动（而非纯知识补充），不要直接改，
   在报告中列为"建议方案"交回主会话讨论

回传报告格式（严格遵守）:
- 扫描范围: 信源 + 候选篇数
- 跳过清单: 每篇一行（标题 + 原因: 已覆盖且完整 / 低价值 / 题目级 trick）
- 沉淀明细: 每条（目标知识库文件 + 小节 + 技术 + 来源 URL）
- 建议方案: 脚本/prompt/架构级的 gap（如有）
- 遗留 gap: 发现但本轮未处理的（下轮素材）
```

## 收到报告后

- 单方向/主题模式：向用户**原样呈现**进化报告，不做二次加工、不自行追加分析。
- `all` 模式：汇总 6 份报告为一张总表——每方向一行（候选数 / 沉淀条数 / 遗留 gap 数），下方附各方向的沉淀明细和遗留 gap 合并清单。

## 约束

- 禁止在当前会话直接执行进化流程（专业流程收口在 evolve agent）
- 一轮只处理一个方向或主题；`all` 模式 = 6 个独立子任务并行派发，禁止合并成单个子任务（上下文保护）
- 用户给 URL 则只处理该信源
- 派发 prompt 中的路径引用保持 `$AGENT_DIR`/`$SHARED_DIR` 变量形式（evolve agent 系统提示中有定义，保证可移植）
